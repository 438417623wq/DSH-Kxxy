# Codex 面板：对齐 VS Code 布局（2026-11-10）

> 后续更新：2026-11-11 已在此基础上加入三协议模型管理、搜索分组、分级诊断、独立 CLI 连接、草稿保护及窄侧栏修复，见 [模型兼容与侧栏优化](codex-model-compatibility-2026-11-11.md)。本页保留当时的实施记录；旧缓存截图不代表新版本已经完成像素或真机验收。

本轮只改**前端结构与样式**（`plugins/dsh-codex-sidebar/lib/client.js`、`web/codex.css`），后端协议、审批门控、打包合同均未改动。目标是让手机上的 Codex 面板在信息结构、控件语汇和交互密度上与 VS Code 里的 Codex 面板一致，而不是继续长得像聊天 App。

## 参照的四处结构

1. **输入框下方只有一行工具条**：左侧 `+` 与「审批方式」胶囊，右侧「模型 · 推理强度」和圆形发送/停止按钮。
2. **审批方式是一个富文本下拉面板**：标题「应如何批准 Codex 操作？」，右上「了解更多」，三档选项各带图标、标题、一句说明，当前档打勾。
3. **模型与推理强度合并成一个面板**，摘要行显示「模型名 + 强度」。
4. **工具记录是可折叠的单行摘要**：状态点、图标、一句话（命令直接显示命令本身）、右侧状态与统计。

## 改动清单

### 输入区（最大变化）

- 原来是「文本域 → @ 文件 / Shift+Enter / 发送 → 模型行 → 应用访问权限」四行堆叠；现在是「引用文件胶囊 → 文本域 → 单行工具条」。
- `+` 是真正的操作入口：引用工作区文件、检查开发环境、新建对话。
- 模式切换（工作区助手 / 仅聊天）从输入框上方的分段控件改为工具条左侧的胶囊菜单，摘要行始终显示当前模式；仅聊天时上方的「开发工具未启用」横幅保留，所以 0.9.36 明确过的「模式可见」没有退化。
- 发送按钮改为圆形图标按钮；任务运行时同位置变成停止按钮，不再把「停止」文字塞进中间行。
- `Shift+Enter 换行` 提示只在桌面（≥768px 且精确指针）显示，手机上不再占一行。

### 审批

- 新的 `ApprovalMenu` 复刻 VS Code 的三档结构与「了解更多」，并在面板底部说明应用权限边界。
- **可用档位没有放宽**：只有「请求批准」（`approvalPolicy: untrusted`）可选；「帮我批准」「完全访问权限」标注「未开放」且不可点，理由写在选项与说明面板里 —— 「会跳过执行前确认」。
- 「了解更多」打开面板内的说明浮层（标题「审批与访问范围」），列出 CLI 以应用身份运行、工作区只是起始目录、文件变更不保证逐次弹窗、任务可随时中断，以及 Android 权限仍然有效。
- 审批卡片移到输入框正上方，改为左侧强调条 + 细边框的卡片：图标、标题、「等待确认」胶囊、命令或差异、一次性说明、拒绝/本次允许。

### 模型

- `ModelMenu` 把模型列表与推理强度合到一个面板：模型行显示名称 + 引擎来源 + 勾选；下方强度用一排胶囊（无/极少/低/中/高/极高）。摘要行显示 `模型名 + 强度`，窄屏（≤420px）隐藏强度徽标以让位给名字。
- 删掉了两个原生 `<select>`（模型、强度），视觉与交互统一。

### 工具记录与差异

- 统一的 `ToolRow`：状态点（完成绿、进行中脉冲、失败红）+ 图标 + 单行摘要；命令行直接用等宽字体显示命令本身，右侧显示文件名的场景显示 `codex-tool-detail`。
- 文件变更卡片显示 `修改 / 新增 / 删除 + 文件名`，展开后每个文件一行：路径、`+n −n`、类型胶囊，下面是带行级着色的差异（新增绿、删除红、hunk 用强调色），长行软换行而不是横向滚动。
- 命令卡片显示 `exit N` 胶囊（成功绿、失败红）与截断提示。
- 代码块增加语言标签与「复制」按钮（`navigator.clipboard`，失败时静默）。

### 其他

- 头部把 `+` 从分段导航里拿出来，成为独立的图标按钮；导航仅保留对话 / 历史 / 设置。
- 空状态加三条建议（点击只填入输入框，不自动发送），并保留工作区胶囊。
- 面板、菜单、浮层都跟随宿主 `--dsw-alias-*` 变量，明暗主题一致；原生引擎仍走单色强调色（`data-engine=native`）。

## 兼容性处理

- `dvh` 全部补了 `vh` 回退（旧 WebView）；浮层容器用 `top/right/bottom/left` 而不是 `inset`。
- 下拉面板宽度用 `min(320px, calc(100vw - 64px))`（左对齐）与 `calc(100vw - 36px)`（右对齐），360px 窄屏实测无横向溢出。
- 手机档位下按钮最小高度 38px、文本域 16px 字号（避免 iOS/部分 WebView 聚焦缩放）。

## 预览与验收方式

仓库外（`.cache/`，已被 gitignore）放了一套一次性夹具，可以在不连模型的情况下看真实渲染：

```bash
# 1) 生成单文件页面（内联 React、client.js、codex.css，fetch/EventSource 用桩接管）
node .cache/codex-layout/build-page.mjs native      # native | custom | custom-chat | approval | 其它=空状态
# 2) 用 CDP 精确模拟手机视口截图
node .cache/codex-layout/shot.mjs "file:///.../shots/page-native.html" out.png 430 932 2
```

`shot.mjs` 第 6 个参数可以传一段 JS，在截图前执行（例如把某个 `details` 展开、点击设置页、注入暗色变量），用于逐个面板核对。实测覆盖：430×932 与 360×800、明暗两套主题、审批面板、模型面板、加号菜单、说明浮层、差异展开、设置页、仅聊天横幅。

## 仍未做

- 「帮我批准」「完全访问权限」保持未开放（需要新的授权决策与后端 `approvalPolicy` 分支，见 `AI_HANDOFF.md`）。
- `@` 文件引用仍是手填相对路径（要带搜索的候选列表需要新的工作区列目录接口）。
- 审批卡片仍在输入框上方而不是严格内联在对话流中（手机上保证可点，避免需要滚动才能处理审批）。
