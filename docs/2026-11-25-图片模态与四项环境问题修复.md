# 图片模态与四项环境问题（2026-11-25，v0.9.89 待发）

上一轮只给了方案（未改文件）。这一轮把方案里标「推荐」的部分全部落地，并按项目
惯例给每条补了可离线跑、可复跑的回归。LibreOffice 那条的「可选增强」**没有实现**，
原因在最后一节写清楚 —— 它不是代码缺失，而是需要一份新的 provision 套件与真机验收。

## 0. 图片模态：只补「目录不知道」的那一格

上游的判定链是

```js
const defaults = catalogModels(provider);   // 自定义 route key ⇒ 空 Map
const base = defaults.get(entry.id);        // ⇒ undefined
input: declaredInput(entry.input) ?? base?.input ?? [...request.defaultInput],
```

`request.defaultInput` 在 profile 没写 `defaultInput` 时由 schema 物化成
`["text"]`，于是「没写 `input`」= 「只收文本」，请求阶段的
`containsImage && !model.input.includes("image")` 必然抛 `UNSUPPORTED_CONTENT`。
桌面端 route key 恰好是内置 provider 名，所以一直正常 —— 这就是「同一份模型桌面能发图、
手机不能」的全部差异。

补丁（`tools/lib/patches.mjs` 的 `patchCatalogModalityFallback`）只做三件事：

1. `base` 命中就不动 —— 目录说了算；
2. `base` 缺失时按 `api` 映射（`google-generative-ai→google`、
   `openai-completions/openai-responses→openai`、`anthropic-messages→anthropic`）
   先精确、再规范化（去 `Pro/`、`openai/` 前缀并小写）匹配；
3. 仍未命中则全局按规范化 id 找**已知多模态**模型。

安全边界：只接受「对话协议 + 声明 `image`」的条目（embedding / 纯文本模型不会被
当成基线）；只继承 `input`/`contextWindow`/`maxTokens`，**不继承** `baseUrl`、
`cost`、`name`（中转域计费与端点都不同）。优先级保持「用户显式配置最高」，为此给
`resolveProfiles → resolveRouteModels` 多传了一个 `defaultInputDeclared`
（区分「显式写了」与「schema 默认的 `["text"]`」—— 不区分的话回退永远没机会生效）。

用户侧**仍然可以**在 `cordis.patch.yml` 里显式写 `input: [text, image]` 覆盖一切，
这条改动只是让「没写」不再等于「不支持」。

## 1. Python：先保证能用，再谈容器

`libexec/python-default/bin` 排在 `PATH` 首位，裸 `python3` 一定进调度器；调度器
原先无条件 `require_ready()`，容器没 provision 就 `exit 127`。运行时自带的原生
bionic Python（numpy/scipy/pandas/matplotlib/torch/sklearn/cv2 + pip 都在）明明可用，
却永远轮不到。

改法（`tools/prebuilt/kxxy-tools/python-default.py`）：

- 新增 `native_fallback()`：`KXXY_PYTHON_REQUIRE_GLIBC` 未设时，按
  `bin/python3 → bin/python → bin/python3.*`（版本号倒序）找 ELF 并 `execve`；
- `bin/python3` 是软链，所以候选先 `resolve()` 再判普通文件（`lstat` 不是 `S_ISREG`）；
- `pip`/`pip3` 走 `python -m pip`；显式 `--venv`、托管 glibc venv、`-m venv`
  一律**不**回退（容器语义不能被悄悄换掉）；
- 回退时清掉 `PYTHON*`/`LD_PRELOAD`（原生解释器不需要 guest 隔离），其余环境原样保留；
- `KXXY_PYTHON_FALLBACK_NOTICE=1` 才往 stderr 打一行说明（脚本会解析 stderr，默认静默）。

`pydeps`（`plugins/kxxy-host/lib/pydeps.mjs`，`REVISION=pydeps@4`）：

- 探针与安装都走**当前生效**的 `python3`（`PATH` 里引擎根内的第一条），与用户敲命令同源；
- 标记文件记 `python` 绝对路径 + `mode`（`glibc`/`bionic`/`dispatcher`）+ 运行时锚
  （`kxxy-runtime.json` 的 `runtimeVersion/hostFingerprint/entries`，退回 `patchset.version`）；
  任一变化即重探，**不再出现「解释器换人但标记仍 ok」**；
- glibc 模式下探针只要求 pydeps 自己装的包（pandas/matplotlib 归 `python-ml` provision 管），
  并给 pip 加 `--break-system-packages`（容器里是 PEP 668 externally-managed）；
- 桌面开发机上 `PATH` 是宿主 Python，`effectivePython()` 只接受引擎根内的条目，
  不会往宿主 user-site 里装东西。

## 2. exiftool：@INC 必须每次重算

只改 `.bashrc` 不够：exiftool 的 shebang 是 `$PREFIX/bin/perl`（回填后为
`<root>/bin/perl`），由 execve 直接解释，**不经过交互式 shell**。所以：

- `plugins/kxxy-host/lib/extinstall.mjs`：`bin/perl` 由软链改为 wrapper（标记
  `KXXY_PERL5LIB_WRAPPER`），按 `$root/lib/perl5`、`$root/extensions/*/lib/perl5`
  的 `<ver>` 与 `<ver>/<arch>` 现算 `PERL5LIB`，再 `exec` 扩展树里的真身（跳过
  自己所在目录，防递归）；`collectBins` 与 `linkExact` 共用，`relinkAll` 不会把它
  换回软链，被删也能重建；
- `EngineConfig.kt`：`.bashrc` 模板升到 `kxxy-shell@8`，同款重算（丢弃引擎根与
  `$HOME/.perl5` 的旧条目、保留用户自加路径），`local::lib` 两条不看存在性
  （否则「先 export 再 cpan」永远装不上）。

`perlLibPath()` 本身没动 —— 它算得对，问题只在时机。

## 3. LibreOffice：为什么没做

方案里的「可选增强」是「glibc 容器里装 Ubuntu arm64 的 `libreoffice-core/writer/calc/impress`
+ `fonts-noto-cjk`，再让 office-to-pdf 优先走 `soffice --headless`」。它需要：

1. 新增一个 `kxxy-glibc-provision office-native` 套件（下载体积、依赖闭包、`apt` 在 proot
   里的可行性都要在真机上验）；
2. 改 `dsh-office-to-pdf` 的后端分派（检测 `/usr/bin/soffice`，失败回落 WASM）；
3. 真机验收：中英文/表格/公式的 docx、xlsx、pptx 各转一轮 PDF，看字形嵌入、内存峰值。

没有设备验收就发一份 400 MB 的 provision 套件，风险远大于收益（上一轮 `manylinux`
垫层的教训）。本轮**维持 WASM 后端**，并把边界写在这里：WASM 不是故障，是当前架构。

## 4. 离线 npm

- `tools/prebuilt/npm/npm-11.21.3.tgz`（2.9 MiB，`npm pack` 产物，自带 1500+ 个
  `bundleDependencies` 文件），刷新步骤见同目录 `README.md`；
- `build-runtime.mjs` 的 `loadBundledNpm()` 解到 `lib/node_modules/npm/`，锚点断言
  `package.json` / `bin/{npm,npx}-cli.js` / `lib/cli.js` / `node_modules/semver`；
- `corepackWrappers(bundledPnpm, bundledNpm)`：`bin/npm`/`bin/npx` 直接
  `exec "$d/node" "$d/../lib/node_modules/npm/bin/*-cli.js"`，`bin/corepack` 增加
  `npm|npm@*` 分支改道本地；
- `RuntimeInstaller.healPackagingWrappers()`：包装器被删时补回的也必须是本地 cli
  （否则「文件被删过」的设备会退回 corepack，症状只在少数设备复发，极难归因）；
- `verify-runtime.mjs` 加反向闸门：`bin/npm` 正文里出现 `corepack/dist/` 即判失败。

## 契约与版本

- `PATCHSET_MARKER` 39 → **40**（`build-runtime.mjs` / `RuntimeInstaller.kt` /
  `test-runtime-capability-contracts.mjs` 三处同步）—— 运行时内容变了（npm 本体、
  `python-default.py`、`pydeps`、`dsh-llm-pi-ai` 补丁），设备必须重新解压；
- 新增回归：`tools/test-model-modality-fallback.mjs`、`tools/test-perl-launcher.mjs`、
  `tools/test-pydeps-probe.mjs`；扩充：`tools/test-python-default.py`（+5 例）、
  `tools/test-runtime-capability-contracts.mjs`（+1 例）、`tools/test-remote.mjs`
  （`.bashrc` 断言从 `@7` 抬到 `@8` 并改锚 `= """` 首行，原先那版**只判「文件里
  有没有这串」**，注释里出现 `# kxxy-shell@7` 就算过，等于什么都没测）。

## `pydeps@4` 的两处附带收紧

- `markerMatches(record, expect)` 从 `ensurePythonLibs()` 的闭包里提成模块级函数，
  经 `__pydepsInternals` 导出给测试 —— 判据（补丁集 / 解释器 / 模式 / 运行时锚四项
  全等）是「陈旧 ok」的唯一防线，运行期完全静默，只能靠回归钉住；
- `effectivePython()` 的 `<root>/bin/python3` 回退原来只判 `existsSync`：`bin/python3`
  万一是个目录也会被当成解释器，之后每次探测都以 EACCES 失败、把 `failed` 写进标记。
  统一改用 `isPlainFile()`（PATH 扫描与回退同一条判据）。
