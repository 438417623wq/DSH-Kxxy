# 系统权限与媒体采集方案（2026-10-29）

## 起因

用户反馈两件事：

1. 设置页没有相机、麦克风的授权入口，而且系统「应用权限」页里大部分权限都是灰的/没有列出来；
2. 给了参考截图（系统对 DSH 的应用权限页）：照片和视频、音乐和音频、文件和文档、短信、
   以及其他权限（发送彩信、剪贴板、设备动作与方向、应用列表、媒体音量控制、桌面快捷方式、
   锁屏显示、后台弹出界面、显示悬浮窗、动态壁纸服务、链式启动管理）。

目标：**清单里声明全，设置页里能逐项授予，点了真的弹框/真的跳页。**

## 一、清单（AndroidManifest.xml）

新增声明分三类，理由各不相同：

| 类别 | 权限 | 备注 |
|---|---|---|
| 媒体与文件 | `READ_EXTERNAL_STORAGE`、`CAMERA`、`RECORD_AUDIO`、`MODIFY_AUDIO_SETTINGS` | targetSdk 28，Android 13+ 仍走 legacy，系统页会拆成「照片和视频」「音乐和音频」两行 |
| 短信 | `SEND_SMS`、`RECEIVE_SMS`、`READ_SMS` | 三条成组：只发不收会让验证码流程断在半路 |
| 其他 | `SYSTEM_ALERT_WINDOW`、`QUERY_ALL_PACKAGES`、`HIGH_SAMPLING_RATE_SENSORS`、`INSTALL_SHORTCUT` | 对应截图「其他权限」里的悬浮窗 / 应用列表 / 设备动作 / 快捷方式 |

**刻意不声明 `READ_MEDIA_IMAGES` / `READ_MEDIA_AUDIO`**：那是 targetSdk 33+ 的通道，
在 28 上申请会立刻被判 DENIED，并计入「拒绝两次不再询问」——之后连真正的对话框都不弹，
等于把媒体权限彻底做死。targetSdk 28 是被 Android 10 的 `execve` 限制逼出来的
（见 `android/app/build.gradle.kts` 顶部注释），不能为了权限改回去。

**锁屏显示 / 后台弹出界面 / 链式启动管理 / 动态壁纸服务**没有对应的 Android 权限，
是 MIUI/HyperOS 安全中心自己加的开关，manifest 里声明不出来，只能跳
`miui.intent.action.APP_PERM_EDITOR`。

## 二、PermCatalog：单一事实源

`android/app/src/main/java/app/kxxy/engine/PermCatalog.kt`

原先权限散在三处（清单、`EngineSupervisor.permissionSnapshot`、`MainActivity` 的
`kxxy://` 桥），加一项要改三个文件，漏一个的症状分别是：

- 漏清单 → 设置页有按钮，点了系统什么都不弹；
- 漏分派 → 点了没反应；
- 漏快照 → 图标永远显示未授权。

现在只有一张表，状态和申请入口都从它派生。四种 kind 的**用户可见差异**是硬约束：

| kind | 授予方式 | UI 表现 |
|---|---|---|
| `RUNTIME` | `requestPermissions` 弹框 | 「去授权」 |
| `SPECIAL` | 跳 Settings 页（无对话框） | 「去开启 / 去设置」 |
| `NORMAL` | 安装即授予（应用列表、媒体音量、传感器、快捷方式） | 只展示，恒带 ✓ |
| `NAVIGATE` | 厂商安全中心 / 应用详情页 | 永远带跳转按钮，不画 ✓ |

状态三态：`true` / `false` / `null`（无法判定）。`null` 绝不画 ✓ —— 谎报已授权比不显示更糟。

## 三、WebView 的媒体采集

`MainActivity.WebChromeClient.onPermissionRequest` 的默认实现是**一律拒绝且不提示**，
网页侧只看到 `NotAllowedError`。所以即便清单声明了、系统里也授权了，网页仍然用不了摄像头。

处理要点：

- 只对 `http://127.0.0.1:` / `http://localhost:` 来源 grant，其他一律 deny（这套桥不是提权口）；
- 只 grant 相机/麦克风两类资源；
- 清单权限没授予时先弹系统框，把 `PermissionRequest` 挂起，`onRequestPermissionsResult`
  回来再作答 —— 并**逐条复核**，不信任 `grantResults` 的下标对齐（部分 ROM 会合并相邻请求）；
- `grant` 的参数只放已授予的那部分：把 CAMERA 一起塞进去会让 `getUserMedia` 抛
  CameraService 的 SecurityException（闪退级），而不是可捕获的 NotAllowedError。

## 四、设置页

权限卡改成与系统「应用权限」页同构的分组（媒体与输入 / 通知与后台 / 文件、应用与桌面 /
短信 / 设备与厂商开关），用户在两处之间对照时不用重新找位置。

- 每行按 `permissions.entries[id]` 渲染三态，按钮直连 `kxxy://perm/request?name=<id>`；
- 底部「一键授予全部权限（还差 N 项）」→ `name=all`，原生把**清单里声明过且尚未授予**的
  运行时权限一次问完（系统会按权限组依次弹框，所以文案不承诺「只弹一次」）；
- 特殊权限不参与「还差 N 项」的计数 —— 它们本来就不能一次性授予，算进来会让按钮永远灰不掉。

## 五、构建

两份产物都要重打，缺一不可：

1. `node tools/build-runtime.mjs --manifest .cache/manifest.json` —— 插件（含本页 web 资源）
   打在 runtime.zip 里，只重打 APK 不会更新设置页；
2. `powershell -File tools/build-apk.ps1` —— gradle + 大资源注入 + 对齐 + 重签。

## 六、遗留

- 「发送彩信」在系统页单列，Android 没有独立的 MMS 权限，走 SEND_SMS；
- 剪贴板读写由 MIUI 后台策略管，无清单权限，已并入「厂商开关」那一行；
- 首次启动（BootstrapActivity）目前不会主动引导授权，用户需进设置页；若要更显眼，
  可在引导页加一个「授予权限」入口。
