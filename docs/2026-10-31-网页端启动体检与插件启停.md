# 体检看不见「页面进不去」+ 插件停不了：2026-10-31 修复

## 现象

真机上报两件事，其实是同一个缺口的两面：

1. **体检 7/7 全绿，对话页却进不去。**
   对话页整页停在 `HARNESS / Failed to load plugins`，下面列着四个插件
   `@neystan/dsh-client-ui-task-board`、`@neystan/dsh-pet`、
   `@neystan/dsh-tool-describe-image`、`dsh-at-file`，每条都是
   `import failed: client-modules: require('@deepseek-ai/dsh-client-runtime/client')
   missed the module table`。回到控制台看体检：全部正常。
2. **想停用出问题的插件，却没有地方可点。**
   官方插件管理在对话页侧栏。对话页白屏时，那个入口正好是打不开的那个。

## 为什么体检会假绿

原有的七项全都只读**磁盘上的配置**：补丁能不能解析、清单里 bundle 在不在、
运行时文件齐不齐。它们回答的是「引擎起不起得来」。

而这次坏在**浏览器里**：官方前端 boot 阶段要按 manifest 解析 client-modules，
桌面端插件声明了移动端没有的客户端入口（`dsh-client-runtime/client`），解析
失败后前端 `catch` 里 `console.error(t)` 然后整页替换成错误页。引擎进程活得好
好的、会话数据库完好、所有配置文件合法 —— 于是体检没有理由报红。

**结论：只读磁盘的体检，原理上无法发现「页面打不开」。必须引入运行期证据。**

## 修法

### 1. 原生把浏览器侧失败落盘

`MainActivity` 的 `WebChromeClient.onConsoleMessage` 已经在转发 logcat，
现在多一步：`WebBootLog.record()` 把命中特征的 console 消息写进
`$DSH_HOME/web-boot/web-boot.json`（环形保留 8 条，同一条 3 秒内去重）。

特征串只收这四类，刻意不收通用 `console.error`：

| 特征 | 含义 |
|---|---|
| `did not activate` | app-boot 的 entry 未激活（前端 boot 抛出） |
| `Failed to load plugins` | 前端错误页标题 |
| `missed the module table` | client-modules 缺模块表，本次事故的根因 |
| `Failed to fetch dynamically imported module` | 动态 import 404，同族故障 |

普通 `console.error` 在插件自己报错时也会出现，但那种页面照常可用 —— 收进来
会把「插件内报错」误报成「页面进不去」，比不报更糟。

引擎每次启动时 `WebBootLog.reset()` 清空：上一轮的失败属于上一轮的插件配置，
用户停用插件、重启过之后必须能恢复绿色。

### 2. 服务端日志也读，格式只解析一次

`engine.log` 里 `dsh-app-boot` 会打：

- `<bin>: warning: N entries did not activate` + 紧随的逐条详情
- `<bin>: skipping profile bundle "pkg": reason`
- `<bin>: startup failed: N required plugins did not activate`

新增 `plugins/kxxy-host/lib/bootreport.mjs` 统一解析这两路来源，并**只认最后
一次 `---- engine start` 之后的内容**（日志是 2 MB 环形，跨轮次串味会误报）。

体检与插件页共用这一份解析结果 —— 两处各写一份正则必然漂移，最后会出现
「体检说加载失败、插件页说正常」这种最难排查的自相矛盾。

### 3. 体检第 8 项「网页端入口」`WEB_BOOT`

| 证据 | 判定 | 含义 |
|---|---|---|
| `startup failed` | BAD | 必需插件没起来，引擎根本没起 |
| 浏览器侧整页失败 | BAD | 用户真的进不去 |
| 只有 optional 未激活 / bundle 被跳过 | WARN | 页面能用，但那几个插件没生效 |
| 都没有 | OK | 本轮日志没有加载失败 |

**关键：`WEB_BOOT` 不参与「修复」力度计算。** 修复（`RecoveryManager`）动的是
profile 补丁与 bundle 列表，而这里的成因是插件与移动端客户端不兼容 —— 既治
不了病，还会连带搬走主题与模型配置（缺陷 BW/CA 的教训）。它只报红，并把用户
推向唯一正确的动作：去「插件」页停用。

体检项里为此加了一个直达按钮（`去停用插件`），不用在五个页签里自己找。

### 4. 控制台新增「插件」页（停用入口）

`plugins/kxxy-host/lib/plugins.mjs` + `/kxxy/api/plugins`、`/kxxy/api/plugins/toggle`。

改的是 profile 清单这一层：

```json
{
  "dependencies": { "@neystan/dsh-pet": "0.4.1" },
  "dsh": { "profile": { "bundles": ["@deepseek-ai/dsh-base", "@neystan/dsh-pet"] } }
}
```

- **停用 = 从 `bundles` 摘掉，`dependencies` 保留**：包体、版本都还在，随时
  一键开回来，不需要重新下载；
- 启用 = 加回 `bundles`；
- 写盘前备份 `package.json.bak-<时间戳>`（只留最近 5 份），写入用临时文件 +
  rename，避免掉电留下半截 JSON —— 那会让引擎下次完全起不来。

**受保护的两类**：核心 bundle（`@deepseek-ai/dsh-base`、`@deepseek-ai/dsh-web-app`、
`dsh-web-mobile`）与 `kxxy-host`。后者是这个控制台自己，停用它等于把停用入口
从里面锁上，之后只能靠 adb 改文件。

页面上失败插件排最前（进入这页的人基本就是来关它的），顶部有红条列出失败的
插件名并提供「一键停用（N）」，改完点「应用并重启引擎」。

## 验收

- `node tools/test-bootreport.mjs` —— **35 项断言全绿**：三种日志格式、跨轮次
  隔离、包名归因、BAD/WARN/OK 三态、level 不被 WEB_BOOT 抬升、停用后
  `dependencies` 保留、核心与宿主拒绝停用、坏清单给出可读原因。
- `node tools/smoke-plugin.mjs` —— 新增 ⑩c：真实 HTTP 打 `/kxxy/api/health`
  与 `/kxxy/api/plugins`，验证「浏览器侧失败 → BAD + level=NONE」、停用真实
  落盘、受保护组件返回 400、清掉记录后恢复 OK。
- `gradle :app:compileDebugKotlin` BUILD SUCCESSFUL。

## 已知边界

- 如果 WebView 直接崩掉（native 崩溃、OOM），console 回调不会执行，抓不到
  记录 —— 那类走原生监管循环重启，不在这一层。
- 浏览器侧记录只在「打开过对话页」之后才存在。全新安装、还没进过对话页时，
  这一项只能靠服务端日志判断。
- 历史 APK 没有 `web-boot` 目录时，这一项按「没抓到」显示 OK（措辞是「本轮
  日志里没有插件加载失败」），不会凭空报红。
