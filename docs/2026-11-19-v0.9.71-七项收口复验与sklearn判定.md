## 2. 内置 joblib / threadpoolctl

`tools/lib/pydeps.mjs` 新增两项纯 Python 依赖：

- `joblib 1.6.0` —— 自带价值：`joblib.dump/load` 的大数组落盘、`Parallel` 多进程；
- `threadpoolctl 3.8.0` —— 查/限 BLAS 线程数。

两者都是 `*-none-any.whl`，走既有「下载 → 校验 sha256 → 解包成文件表」流水线，`tools/build-runtime.mjs` 的 `REQUIRED_PURE_PY` 加了 `joblib/__init__.py`、`threadpoolctl.py` 两条点名断言 —— 少一个就直接构建失败，不会又出现「装进去了但 import 不到」。

顺带把 `PATCHSET_MARKER` 提到 `kxxy-patchset@30`：`isComplete()` 的十六条锚点只判「文件在不在」，**新增文件它是看不见的**，不涨标记设备就会继续跑旧的一份 site-packages。

### 2.1 但 joblib 只能串行：Android 没有 `/dev/shm`

真机 `import joblib` 会带一条警告：

```
/multiprocessing_helpers.py:44: UserWarning: [Errno 2] No such file or directory.
    joblib will operate in serial mode
```

顺着查到根上，**这不是 joblib 的问题，是这台设备上 `multiprocessing` 本身就不可用**：

```
_multiprocessing.SemLock(0,0,1,name='/t1')      → FileNotFoundError: [Errno 2]
multiprocessing.get_context('fork').Process(...) → FileNotFoundError: [Errno 2]（SemLock 构造处）
```

bionic 的 `sem_open` 走 `/dev/shm`，而 Android 没有这个目录（`/dev` 是 devtmpfs，应用无权创建）。
所以：`joblib.Parallel(n_jobs>1)` 静默退化为串行、`multiprocessing.Pool/Queue` 不可用、
`torch.utils.data.DataLoader(num_workers>0)` 不可用（`num_workers=0` 正常）。
线程池（`concurrent.futures.ThreadPoolExecutor`）、OpenMP/BLAS 多线程不受影响。
这条是平台边界，跟 glibc 那条同级，但影响面更广 —— 文档里要写明，别让人以为是装坏了。


## 3. sklearn / cv2 为什么仍然缺（证据链）

### 3.1 Termux 生态里没有

| 索引 | `python-scikit-learn` | `python-opencv` | `python-joblib` |
| --- | --- | --- | --- |
| termux-main（3047 包，线上复核 200 OK） | ❌ | ❌ | ❌ |
| TUR（`tur.kcubeterm.com`，603 包） | ❌ | ❌ | ❌ |
| TUR 构建脚本目录（GitHub API，315 项） | ❌（只有 `python-scikit-image`） | ❌ | ❌ |

### 3.2 PyPI 只有 glibc 轮子，而 bionic 加载不了

有轮子，且 ABI 匹配我们的 python 3.14：

```
scikit_learn-1.9.1-cp314-cp314-manylinux_2_27_aarch64.manylinux_2_28_aarch64.whl   8.5 MB
opencv_python_headless-5.1.0.95-cp37-abi3-manylinux2014_aarch64.whl                34.1 MB
```

真机实测（`.cache/shim.sh`），把冲突一个个按 glibc 的 soname 补软链：

```
第 1 轮  cv2     ImportError: dlopen failed: library "libavcodec-8390d082.so.63.1.102" not found
         → 补 LD_LIBRARY_PATH 到 opencv_python_headless.libs
第 2 轮  cv2     ImportError: dlopen failed: library "libdl.so.2" not found
         → 建 libdl.so.2 → /system/lib64/libdl.so 等垫片（libc.so.6 / libm.so.6 / libpthread.so.0
            / librt.so.1 / libresolv.so.2 / libz.so.1 一起），另从 Debian arm64 取
            libstdc++.so.6.0.30 / libgcc_s.so.1 / libgomp.so.1
第 3 轮  cv2     ImportError: dlopen failed: library "ld-linux-aarch64.so.1" not found
         → 软链到 /system/bin/linker64
第 4 轮  cv2     ImportError: library "ld-linux-aarch64.so.1" ... is not accessible
                 for the namespace "(default)"
```

第 4 轮是终点：**Android 的链接器命名空间不允许从这个路径加载 `ld-linux`**，这是 bionic 的硬限制，不是少补一个软链能绕的。sklearn 那一侧同理（`sklearn.__check_build._check_build` import 失败，`.so` 的依赖同样落到 glibc 专有 soname 上）。

顺带一个结论值得记住：**glibc 的 `.so` 在 bionic 上是"能过依赖解析到某一层、但走不到最后"**，个别只有 `libc/libm` 依赖的简单扩展偶尔能加载成功，会让人误以为这条路通。别拿个例当通例。

### 3.3 引擎不带 C/C++ 工具链，源码编译这条路也堵着

`pip install scikit-learn`（源码）需要 clang/g++；引擎里**故意没有** gcc（`tcc` 因 bionic 头文件直接 `#error`，`nim` 生成的 C 也没编译器可用，两者都只在池里不发）。`zig cc` 理论上能当 C 编译器，但交叉到 Android 需要 NDK 的 bionic 头，设备上没有。

### 3.4 结论

- 想要 sklearn / cv2，只剩**在构建机上用 NDK 交叉编译**一条路（`sdk/ndk/28.2.13676358` 是现成的）。
- sklearn 的难点：1.9.1 的 `meson.build` 在交叉模式下没法内省目标 python（`import('python')` 要跑目标解释器），只能绕开 meson 手工 cythonize + clang++ 编 40 多个扩展，工作量按天算。
- cv2 更重（OpenCV 全量 C++，还要 ffmpeg/gstreamer 之类的可选依赖），基本不考虑。
- 因此当前版本**不再宣称**这两个包可用；需要时再单独开一轮交叉编译专项。
