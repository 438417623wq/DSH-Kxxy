# DSH Kxxy 控制台 · 全站改版方案（v2）

> 上一版《2026-11-16-手机端界面改造方案》只改了三个屏（概览 / 远程 / 设置）；
> 这一版把那套排版抽象成**一套组件与规则**，覆盖控制台全部五个视图 + 弹层 + 远程会话设备条。
> 设计稿：`docs/mockups/2026-11-16-控制台-全站改造稿.html`（可编辑源，单文件自包含），
> 截图：`2026-11-16-控制台-浅色五屏.png`（①–⑤）、`2026-11-16-控制台-深色弹层会话.png`（⑥–⑧）。

---

## 0. 一句话结论

现在控制台的问题是**「每个功能都长成一张卡」**：`.card` 是唯一容器（`padding:16px`、
`radius:16px`、`margin-bottom:12px`），于是概览页摆着 **9 张同构卡片**、插件页在第一个插件
之前要塞进 4 段说明、扩展页 26 个扩展是 26 张卡。信息量没变，但每一屏都被抬高了 2–3 倍。

改法只有一句：**卡片只用来分组，行用来承载内容**。

## 1. 设计系统（先定这套，再谈页面）

### 1.1 颜色

浅色/深色各一套，**不要从 `--dsw-alias-bg-layer-*` 推**——浅色主题里
`bg-base`/`layer-1`/`layer-2`/`layer-3` 全是 `#fff`（实测），推出来的「分层」全是同一个白。

| `--dsl-card` | `#FFFFFF` | `#1B1B1D` | 分组卡、导航条、底栏 |
| `--dsl-inset` | `#F7F8FA` | `#232326` | 行内图标底、次级块、seg 轨道 |

### 1.3 尺寸

- 分组卡 `radius 14`、`0 0 0 1px var(--dsl-line)`（**不用 border**，避免 1px 参与盒模型）

- 行内图标 32×32 / `radius 9`；hero 里用 42×42 / `radius 12`
- 页面左右留白 14、组间距 14、组标题与卡 7
- 触控目标 ≥ 44：行整行可点，按钮 min 32 并靠行内 padding 补足

## 2. 逐屏改造

### ① 概览（问题最集中）

现状：`hero-status-card` + 3×`metric-card`（各 98px 高）+ 远程卡 + `health-hero` +
两张 `fold-card` + 补丁卡 = **9 张卡**，四张在讲同一件事「引擎好不好」。

改法：
1. **四卡合一**：hero（19px 结论 + PID/arch/Node 三个 mono chip）+ 底部三分栏
   指标条（内存 / 运行 / 端口），高度 76+56=132，比原来 76+12+98=186 少 54。
2. **诊断三行一组**：启动体检、运行时完整性、宿主补丁各占一行，行尾直接给结论
   （`通过` / `7 / 7` / `13 项生效`），点行进原有折叠内容。原来三张卡 ≈ 220，现在 3×52+27=183。
3. **维护收进弹层**：一键验收、修复命令链接、直链镜像、ghraw、插件管理这 7 个按钮
   只留一行「服务与排错 ›」，点开是底部弹层（⑦）。原来 `danger-actions-grid` 是 4 行 ≈ 200。
4. 远程接入仍是独立一行，行尾直接是「连接」主按钮——概览上唯一的主按钮。

### ② 扩展

现状：顶部一张 90px 说明卡 + 分类 chips + 每个扩展一张 120px 卡（含类目标签、激活、卸载两行按钮）。

改法：
- 说明卡 → 一行 `.dsl-note`（40px），只留「本地解包、不联网」+ 一句口播。
- 每个扩展 → 一行：图标、名称、`语言与编译链 · v3.12.4 · 62 MB`、右侧**一个**动作
  （已激活显示绿色 chip；未激活显示「激活」soft 按钮）。26 项从 ~3100px 压到 ~1600px。
- 分组保留（已激活 / 类目），但标题移到卡外，组内不再重复「已激活」标签。
- 多选、批量条保持不变，只是把 `.ext-batch-bar` 换成 sheet 风格。

### ③ 插件

现状：第一个插件之前有 4 段内容（标题+两按钮、范围说明、搜索、筛选 chips ≈ 260px），
外加一张 90px 说明卡；异常插件的信息（错误栈）藏在卡片下半部分。

改法：
- 标题收进顶栏，右侧只留「刷新」和「安装」；`本地安装/安装插件` 的入口进安装弹层。
- 搜索框 38px + 筛选 chips 30px，直接跟列表。
- 插件 → 一行 + 右侧开关；**异常行**把错误首行用 mono 红字放在副标题位
  （`加载失败 · Cannot find module 'sharp'`），行尾给「停用」。
- 核心组件仍是折叠行（`18 个 · 不提供停用开关`），不再是单独的卡。
- 「有变更待生效」保持吸底条，压到两行文字 +「应用并重启」；FAB 会盖在它上面（Material 的 snackbar 层叠关系）。

### ④ 远程接入

现状：未连接时第一屏 90% 是四步教程（含 git 命令、三种网络模式对照），
已配对设备列表被推到第三屏以下。

改法（沿用第一版结论，补上状态块与设备行细节）：
1. 顶部状态块：未连接时显示「未连接 + 一句话 + 已配对/上次成功/通道 三指标」，
   已连接时换成「已连接 · 局域网 12ms + 断开」。
2. 设备列表前置：一行一台，`名称 / 地址·时间 / 通道 chip + 连接`；公网设备 chip 用蓝色区分。
3. 添加电脑：seg 切「扫码 / 粘贴」，扫码页只留二维码区 + 一句提示。
4. 四步教程收成一行「第一次连接？电脑上装个插件」，默认折叠；**没有任何设备时**才展开。
5. 底部一句脚注负责说清「状态只是上一次的结果」，不再用整张 `remote-note-card`。

### ⑤ 设置

现状：外观三张卡、16 项权限折叠卡、三级大卡 + 大按钮、4 个开关、关于入口、
`danger-actions-grid` 7 个按钮，纵向 ~1400px。

改法：
- 外观 → 一条 seg（跟随系统 / 浅色 / 深色），60px。
- 权限与保活 → 一组四行：系统权限（chip 待授权 + chevron 展开 16 项）、息屏、前台保活、无障碍。
- 运行权限等级 → **一条 seg（标准 / 增强 / 完全）+ 一句说明 + 应用按钮**。
  三行单选在 393 宽度里挤，切级本来就要重启一次，分段式更省也更准。
- 维护与关于 → 一组两行，危险操作全部进弹层，红字只在弹层里出现。

## 3. 跨页一致性规则（评审时按这 6 条挑毛病）

1. **一屏只有一个主按钮**：蓝色实心 ≤1 个，其余一律 soft。
2. **组标题在卡外**，卡内不再重复一级标题（现在每张卡都是「15px 标题 + 12px 副标题」，重复 6 次）。
3. **行尾最多两个元素**：`value | chip | switch | button` 四选一，最多再跟一个 chevron。
4. **状态必须带文字**：不允许只有颜色点；chip 的 `ok/warn/err/blue` 四色之外不加色。
5. **说明文字不占卡**：能进 `row-sub` 就进，进不去进 `dsl-note`（一行），再不行进弹层。
6. **折叠项标题自带结论**：`宿主补丁 · 13 项生效`，而不是 `宿主补丁 ›`。

## 4. 落地映射（改哪里）

### 4.1 `plugins/kxxy-host/web/host.css`

- 在 `body` 与 `body[data-ds-dark-theme]` 上各加一段 `--dsl-*` token（照 1.1 表），
  **不要**改 `.card` 的默认值——`.card` 在弹窗、插件卡里还在用，改了会一起变。
- 新增 `.dsl-*` 组件类，前缀隔离，老类全部保留。迁移方式是「index.html 换 class」，
  而不是「删 CSS」，这样任一项出问题能单屏回滚。
- 深浅色只走 token，不写 `body.dark .dsl-xxx` 的分支。

### 4.2 `index.html`（结构，动前先抄一份 id 清单）

**所有 id 都是 `host.js` 的锚点，重排时必须原样保留**：`metric-memory / metric-uptime /
metric-port`、`engine-*`、`health-*`、`runtime-*`、`remote-*`、`plugin-*`、`perm-*`、
`priv-cards`、`selftest-*`、`about-*`。

- 概览：`hero-status-card` + `metric-grid` → 一个 `.dsl-hero`；两张 `fold-card` +
  `patch-card` → 一组三行；`danger-actions-grid` 七按钮 → `.dsl-sheet`（弹层放在 `.app-main` 外，
  和现有 `plugin-sheet-mask` 同一层，避免被 `view-pane` 的 `transform` 关住）。
- 设置：`appearance-list` / `priv-cards` 的容器保留 id，`host.js` 改成往里注入 `.dsl-seg`。

### 4.3 `host.js`（渲染函数，改 5 处）

| 函数 | 现状输出 | 改成 |
|---|---|---|
| `renderHealth` | 三个独立卡 + 两处折叠 | 组内三行（每行一个 `dsl-row`） |
| `renderExtensions` | 每个扩展一张卡（`renderExtCard`） | 一行，动作位二选一 |
| `renderPlugins` | 插件卡 + 下半区错误信息 | 一行 + 右侧开关；错误进副标题位 |
| `renderRemoteList` | 设备卡 | 设备行（通道 chip + 连接按钮） |
| `renderPermissions` / `renderPrivCards` | 16 项列表 / 三张大卡 | 组内行 / 一条 seg |

**不要碰** `compat.js` 的 `MOBILE_LAYOUT_CSS` 与 `WebReadiness.MOBILE_FRAME_CSS`：
`tools/check-mobile-layout.mjs`、`check-mobile-frame.mjs` 锁的是官方对话页的主列宽度，
它们变红就说明选择器越界了。

### 4.4 构建

改 `host.css` / `host.js` / `index.html` 需要更新设备上的 `kxxy-host` 插件资源。
现有 `restamp-mobile-plugin.mjs` 只处理 `dsh-web-mobile`，所以要么跑全量
`build-runtime.mjs`（重打 1.9 GiB），要么先补一个 `tools/restamp-host-plugin.mjs`
（照 mobile 那份改成只换 `plugins/kxxy-host/web/**` + 重算 host fingerprint）。**建议先补脚本。**

## 5. 兼容与风险

| 项 | 说明 |
|---|---|
| WebView 104 | 禁用 `:has`(105)、`color-mix`(111)、`@container`(105)、`dvh`(108)、嵌套 CSS(112)。设计稿里已全部避开，除 `color-mix` 用两套字面量替代。 |
| `.card` 全局复用 | 插件安装弹层、关于弹窗、扩展卡都用它；新增 `.dsl-*` 而不是改默认值。 |
| `!important` 覆盖 | `host.css` 约 1745 行的「已激活组折叠」用 `!important` 压内联 `display`；扩展改成行以后这段要重写，否则会把行也压掉。 |
| 折叠与 autofocus | `.dsl-row` 作为 `<summary>` 时，默认三角要 `::marker{content:''}` + `list-style:none`。 |
| 深色下的浅色兜底 | `--fb-*` 那套兜底别删，`theme.css` 解析失败时它是唯一防线。 |
| 重打 APK | 只有 ⑧ 会话设备条（`RemoteBar.kt`，dex 里）需要重打；单包 2.1 GB，单独一批。 |

### 8.2 与设计稿的偏差（实现时按真实 DOM 调整）

1. **扩展行高 77–78px，不是设计稿估的 52–58。** 行内是三段文字（名称 / `约 82 MB · 内置包池` /
   一行描述），缩到 52 需要砍掉描述行；但描述是「这东西干什么用的」，砍掉就只剩名称，反而要跑去
   详情里找。折中是保留一行 clamp 描述，密度收益仍然成立（3100 → 1099px，一屏 8 项）。
2. **设置页「运行权限等级」没有改成 segmented。** 设计稿里是「三行单选 → 一条 seg」，
   但那三行由 `host.js` 的 `renderPrivCards` 动态生成（含 `已保存 · 重启引擎后生效` 徽章与
   每行独立的点击态），改成 seg 要么重写渲染函数、要么把待生效状态塞进 seg 里 —— 都不属于
   纯样式批次。本版只把三张卡合并成一组行，选项语义与交互原样保留。
3. **维护区用 `<details>` 折叠，不是底部弹层。** 弹层要新增一层 DOM + 焦点陷阱 + 关闭手势，
   而折叠只需要一个原生元素，键盘与无障碍行为免费。七个按钮进去六个，主按钮「重启引擎」留在外面。
4. **远程页「添加电脑」保留扫码为主 + 粘贴折叠**，没有做「扫码 / 粘贴」两个 tab ——
   tab 会让默认态多一行且要维护选中态，折叠同样能把 312px 压到 ~120px。

### 8.6 装到真机上才发现的三处指纹（补记）

第一次重封只换了 `lib/node_modules/kxxy-host/**` 与 `build.json`，包能装上、能签名、
条目数也对，但真机启动直接停在「遇到一点小麻烦」：

```
native-boot-failure.json  {"phase":"install","exception":"Refused",
  "reason":"Python 离线修复：目标宿主指纹与 APK metadata 不符；不会自动清空或重装用户运行时"}
```

宿主指纹在**三个地方**各存一份，必须同时前进，缺一处就是「装完新包反而开不了机」：

| 位置 | 字段 | 谁在读 |
|---|---|---|
| `runtime.zip` 内 `kxxy-runtime.json` | `plugins.hostFingerprint` / `hostMarker` | 设备侧 `PythonRuntimeRepair` 的 lineage 校验 |
| `runtime.zip` 内 `kxxy-host/lib/.fingerprint` | `fingerprint:` 行 | 安装器锚点 8（决定要不要重装运行时） |
| `assets/python-repair/manifest.json` | `baseHostFingerprint`（设备**当前**该有的）/ `hostFingerprint`（这次要装到的） | `PythonRuntimeRepair` 判断能否离线修 |
| `assets/meta/build.json` | `kxxyHostFingerprint`、`pythonRepairManifestSha256` | 原生探针的期望值来源 |

脚本现在把这四处一起改，并且加了两条护栏：

1. **输入必须是干净基线。** 拿一份已经重封过一半的 zip 当输入，`previous`（旧字节）
   就指向了新内容，设备端三方比对必然失败。脚本会比对 `lib/.fingerprint` 与
   `kxxy-runtime.json` 的声明，不一致直接拒绝：
   `输入运行时自相矛盾：lib/.fingerprint=… 而 kxxy-runtime.json 声明 …`
2. **`--assets` 默认指向 `android/app/src/main/assets/python-repair`**，重封时顺手
   重算 `payload.zip` 与 `manifest.json`，同时回写 `build.json` 的
   `pythonRepairManifestSha256`。

还有一处：**修复包里不只有宿主的 7 个文件**。第一次重算时只带了
`PYTHON_HOST_FILES` + `kxxy-runtime.json`，设备给出的拒绝理由是
「清单缺少 Python 原生后端、包元数据或版本文件」。完整清单是
61 个（8 个 host + 53 个受管 Python：`lib/python3.14/site-packages/**`、
原生后端 `.so`、`bin/python3`、dist-info 元数据与版本文件）。
这些字节这次重封根本不动，所以脚本直接从**上一份 `manifest.json` 抄路径、
从输入 zip 取值**，既不依赖打包机上的 wheel 归档，也不会与全量构建漂移；
上一份 manifest 的 `baseHostFingerprint` 与输入运行时不一致时会直接报错。

另外记一笔打包环境的坑：非交互 shell 里 gradle 调不到 `git`，`versionName` 会静默
掉成 `0.0.0+nogit`、`versionCode` 退回落盘下限。打包前把
`E:/workbuddy/workbuddy/resources/vendor/PortableGit/mingw64/bin` 塞进 PATH，
或用构建脚本提供的 `KXXY_VERSION_NAME` / `KXXY_VERSION_CODE` 显式指定。

### 8.7 第四次重封：指纹对了，样式还是旧的（补记）

指纹四处对齐、包也装上了、控制台确实是新结构，但**视觉全丢**：底栏中央那个
`.dsl-fab` 变成一只盖住半屏的紫色大气泡，扩展列表整块空白。

逐层查下来，问题不在构建，在**设备侧的更替边界**：

| 文件 | 设备上的 mtime | 内容 |
|---|---|---|
| `web/index.html` | 21:48（本次安装） | 新版 |
| `web/host.js` | 21:48（本次安装） | 新版 |
| `web/host.css` | **17:06（上一版）** | **旧版，`dsl-` 规则 0 条** |

两个原因叠加：

1. **`isComplete()` 的锚点 11 只看 `kxxy-host/patchset.version` 这一行**。编号不变
   就判「运行时完整」直接返回，`lib/` 根本不重解压 —— 而重封时我只换了文件和指纹，
   没动这个标记。
2. **Python 增量修复的受管名单不含样式表**：`PythonRuntimeRepair.HOST_WEB_FILES`
   只有 `index.html` 与 `host.js`。于是每次装机都会刷这两个，`host.css` / `theme.css`
   / `compat.js` / `modern.js` 永远留在上一版。

结果就是「新 DOM 跑在旧 CSS 上」：`.dsl-fab` 失去 `width/height:54px` 与圆形背景，
`<a>` 里的 `<svg>` 退回替换元素默认的 300×150（`stroke="currentColor"` 取到链色），
被放大成半屏气泡；`.dsl-group` / `.ext-card` 这一整套组件层不存在，列表自然塌掉。

修法是把补丁集编号升到 `kxxy-patchset@26`（`build-runtime.mjs` 与
`RuntimeInstaller.kt` 两处必须一致），强制存量设备重解压一次。`restamp-host-plugin.mjs`
现在会自动做这件事，并从 `build-runtime.mjs` 取值、与 `RuntimeInstaller.kt` 对账，
不一致直接拒绝出包（否则设备会判「标记不符」而无限重装）。

同时补了两条护栏：

- 标记必须写进**替换集**（`files`）而不是只放进 `kept`：写出阶段只重写 `files`
  里的条目，`kept` 仅参与指纹计算与「保留 N 个」的计数。第一次改就漏在这里 ——
  指纹算了新值，标记文件却原样拷贝，`zip` 里仍是 `@25`。
- 顺手同步 `.cache/build-meta.json`（构建机副本）。`verify-runtime.mjs` 的锚点 8
  拿它对账，不同步会把「产物已经对了」报成
  `宿主插件内容指纹：✗ 与 .cache/build-meta.json 不符`，白查一轮。

**给后来者的判据**：改 `plugins/kxxy-host/` 下任何前端资源，都要问一句
「`HOST_WEB_FILES` 里有它吗」。没有 → 必须升补丁集编号；有 → 编号不变也能到设备上。

### 8.8 把这条件判据变成结构性保证

8.7 的修法（升补丁集编号）能救那一次，但没解决根因：名单本身是残缺的。
所以两处一起改：

| 位置 | 原来 | 现在 |
|---|---|---|
| `PythonRuntimeRepair.HOST_WEB_FILES` | `index.html`、`host.js` | 再加上 `host.css`、`theme.css`、`compat.js`、`modern.js` |
| `tools/lib/python-runtime.mjs` 的 `PYTHON_HOST_FILES` | 同上两项 | 与 Kotlin 逐项同名（两处必须同步，已写进注释） |

修复包因此从 61 个文件变成 65 个（12 host + 53 python），`payloadSize` 554 916 B。
**判据从「记得升编号」变成「`web/` 下的资源自动随修复下发」** —— 以后改样式不必再
让设备重解压 790 MiB。

顺带修了 `restamp-host-plugin.mjs` 的基线校验：原来只接受「输入 zip 的指纹等于上一份
manifest 的 `baseHostFingerprint`」，而一旦某一版真的发出去了，下一个包就再也接不上
（只能退回 0.9.58 那份老包当基线，设备每次都判「不适用」而白重装）。现在两种都收：

```
· 等于 baseHostFingerprint —— 在同一基线上继续重封
· 等于 hostFingerprint     —— 上一版已发布，从它接续（新的 base 就是它）
```

第二种才是常态。它的正确性建立在一条不变式上：**输入 zip 的字节必须等于设备上现在的
字节** —— 修复包的 `previousSha256` 直接取输入 zip 的字节，设备做三方比对时才能命中。

### 8.9 第 5 次验收：行的宽度预算 + 空页

补丁集到位后样式终于在设备上生效，暴露出两个与样式表无关、之前被「CSS 全丢」遮住的
问题：

**① 扩展行被挤成两行。** 设计稿的标题是 `FFmpeg 6.1.1`（短），真机数据是
`FFmpeg 多媒体工具链` + 独立的版本徽章（长一倍）。一行可用宽度是这么分的：

```
393 − 32(页边距) − 24(卡内边距) = 337
337 − 20(勾选框) − 10 − 32(图标) − 10 − 124(尾部) − 10 = 129px   ← 正文只剩这些
```

124px 的尾部是「绿色胶囊『已激活』+ 卸载按钮」两件套。正文 129px 装不下 ~142px 的标题，
于是折在最后一个字上（`FFmpeg 多媒体工 / 具链`），同一列表里出现两种行高。

修法按全站规则走 —— **状态归组标题，动作只留一个**：已激活的条目本来就只出现在
「已激活 N」这一组里，胶囊是纯冗余。去掉胶囊、尾部改成单个「卸载」后正文回到 191px，
标题（142 + 版本徽章 30）刚好放下。同时给 `.ext-name` / `.ext-meta` 补上
`nowrap + ellipsis + min-width:0`，让超长名字截断而不是折行。

**② 扩展页在「全都装完了」的设备上是空白的。** 「已激活」组默认折叠（v1 的设定，
目的是给「获取」让位），但这台设备 24 项全部已激活、其它分组被 `filter(g => g.items.length > 0)`
过滤掉 —— 于是整页只剩一行组标题，下面一片白，看起来像加载失败。

改成：**只有还存在可安装分组时才默认折叠**。为此补了一个 `collapsedGroups` 集合，
否则用户手动收起的分组会在下一次 5 秒轮询里被默认态重新展开（展开态是模块级的，
`renderExtensions` 每次重建 DOM）。

两条都先在本地 393px 夹具上验过再打包 —— 用真机的长标题与 `约 116.8 MB · 内置包池 ·
零联网` 这串 meta 当数据，确认标题/副标题单行、右侧只剩一个按钮、行高一致。
