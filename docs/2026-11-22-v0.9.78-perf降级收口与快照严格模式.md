# v0.9.78：perf 降级收口、rsync 严格模式与去重加固

承接 v0.9.77 的真机反馈。这个版本不再试图“解决”设备策略拒绝的硬链接和
PMU，而是把普通 APK 内能保证的行为做实、做诚实：

- `perf` 的 PMU 失败不再等于整个命令失败；能力列表、退出码和报告分开表达。
- `rsync` 增加“必须硬链接，否则不传”的严格模式；显式软链去重改成原子替换。
- 真实硬链接和真实 PMU 仍明确标为环境限制，不提供伪造结果。

## 1. perf 1.1

### `perf list`：PMU 与降级能力分列

原来所有事件只有一个 ✓/✗，应用域里 `perf_event_open` 全部 EACCES 时，看起来
像整个 perf 都不可用。现在输出：

```text
    PMU        event                      fallback             description
    ✗ EACCES   cycles                     —                    CPU 周期
    ✗ EACCES   task-clock                 stat:rusage//proc   任务占用 CPU 时间
    ✗ EACCES   cpu-clock                  stat:rusage//proc, record:ptrace
```

最后单独打印当前 SELinux 域和模式，并说明：PMU 全 ✗ 只代表硬件/内核计数不可用，
`stat`/`record` 仍可能走 fallback。

### `perf stat -e cycles`：不再用 task-clock 冒充成功

- 没显式指定事件时，降级统计仍输出 task-clock、page-faults、context-switches，
  返回 0。
- 显式请求的全是 PMU 事件（如 `cycles`）时，降级路径执行完目标后返回 1，并明确
  “以下显式请求的事件需要 PMU”。
- `cycles,task-clock` 这种混合请求只输出 task-clock，同时说明 cycles 缺失，返回 0。
- `minor-faults` / `major-faults` 分别输出，不再始终合并成 page-faults。

### `perf record`：降级必须真的继续，退出码保留目标结果

- auto 模式在 PMU 打不开时打印“切换到 ptrace 降级采样”，然后继续采样。
- 降级没抓到样本（目标太快退出）时仍写出合法的空 `perf.data`；`perf report`
  会明确显示没有样本。
- `-- cmd` 模式保留目标退出码；目标被信号终止时返回 `128 + signal`。
- `-p PID` 模式没有可回收的子进程状态，只有采到样本才算成功；空样本返回 1。
- 任何异常/中断仍通过 `try/finally` detach 并 SIGCONT，避免目标永久停在
  SIGSTOP。
- `KXXY_PERF_MODE=pmu` 仍是严格模式：只要 PMU 不可用就失败，不自动降级。

版本号改为 `kxxy-perf 1.1`，便于现场确认跑的不是旧运行时。

## 2. rsync：三种模式边界清楚

### 默认

```sh
kxxy-rsync -a /src/ /snap2/ --link-dest ../snap1
```

硬链接探针失败时警告可能退化为复制，然后原样执行 rsync。退出码保持原生结果。

### 必须硬链接

```sh
KXXY_RSYNC_LINK_REQUIRED=1 \
kxxy-rsync -a /src/ /snap2/ --link-dest ../snap1
```

设备不支持硬链接、目标是远端或 dry-run 导致能力无法确认时，在传输前退出 1。
`KXXY_RSYNC_LINK_STRICT=1` 保留为同义兼容名。

### 显式空间去重

```sh
KXXY_RSYNC_DEDUP=symlink \
KXXY_RSYNC_DEDUP_VERIFY=1 \
kxxy-rsync -a /src/ /snap2/ --link-dest ../snap1
```

- `KXXY_RSYNC_DEDUP` 只接受空值或 `symlink`，拼错直接退出 2，不执行传输。
- rsync 成功后才开始去重；dry-run 不修改。
- 只处理基准与目标两侧都存在的普通文件。
- 默认按大小 + mtime；`VERIFY=1` 时逐字节比较。
- 替换方式改为：同目录创建临时相对软链 → `os.replace()` 原子替换。失败时删除
  临时链接，原目标文件仍在，不再有“先 unlink 再 symlink”的丢文件窗口。
- 结束打印替换数、保留独立副本数和释放的 MiB。

代价不变：`lstat` 能看到软链；删除基准快照会让目标侧断链。

## 3. 未承诺的部分

- 普通 APK 内的 `link(2)` 仍 EACCES。`ln` 保持 coreutils 语义，失败即退出 1，
  不创建目标，也不把 proot 的 `--link2symlink` 当真实能力。
- 应用域的 `perf_event_open` 仍受 seccomp/SELinux 限制。真实 PMU 仍需要
  `adb run-as` 或独立特权 helper；root helper 不在本版本默认链路中。
- 原生 `python3.14` 仍没有 sklearn/cv2。默认 `python3`（glibc 3.12）六包全集
  不变，reprovision 目标也不变（glibc 扩展仍为 `24.04.3-r3`）。

## 5. 验收命令

```sh
# 能力矩阵：PMU 列和 fallback 列必须分开
perf list

# 默认降级统计：应返回 0 并输出 msec/缺页/切换
perf stat -- python3 -c 'sum(range(2000000))'

# 只有 PMU 事件：应明确说明需要 PMU，返回 1
perf stat -e cycles -- true

# 降级采样：用持续数秒的负载，不要用 true 判断采样是否可用
perf record -F 100 --duration 3 -o perf.data -- \
  python3 -c 'x=0
for i in range(10000000): x += i*i'
perf report -i perf.data

# 严格 rsync：不支持时不得传输
KXXY_RSYNC_LINK_REQUIRED=1 kxxy-rsync -a /src/ /snap2/ --link-dest ../snap1

# 显式去重：cmp 一致，readlink 显示软链
KXXY_RSYNC_DEDUP=symlink KXXY_RSYNC_DEDUP_VERIFY=1 \
  kxxy-rsync -a /src/ /snap2/ --link-dest ../snap1
```
