# 环境问题清单修复（v0.9.62）

> 输入：`环境问题清单(1)(1).txt`（2026-11-16，九项 + 附录）
> 结论先行：**九项里只有三项是真缺陷（6 tmux / 8 perl cpan / 9 Python 库），
> 三项在真机引擎环境里本来就正常（1 ruby / 2 maven / 4 exiftool / 7 go），
> 一项是「安装期参数缺一个」（3 LaTeX 格式构建），一项是探测方式问题（5 gdb）。**
> 下面逐条给证据、给改法。

## 为什么清单会「看起来全崩」

清单里的 1/2/3/4/5/7 有一个共同点：**它们的失败都能被引擎环境变量治好**。

| 项 | 治它的变量 |
| --- | --- |
| 1 ruby 的 `$LOAD_PATH` | `RUBYLIB` |
| 2 maven 的 `MAVEN_HOME` | `PATH` 里的 `<root>/opt/maven/bin` |
| 3 texlive 的格式/引擎 | `TEXMFCNF` / `TEXMFROOT` / `TEXMFVAR` |
| 4 exiftool 的 `@INC` | `PERL5LIB` |
| 5 gdb 的 Guile 启动 | `GUILE_LOAD_PATH` / `GUILE_LOAD_COMPILED_PATH` |
| 7 go 的 `GOPROXY` | `GOPROXY` / `GOSUMDB` |

在真机上按 `EngineConfig.buildEnv()` 逐条导出后复测（Redmi K60 Pro，0.9.61）：

```
$ ruby -e 'puts $LOAD_PATH.size'        → 10          # 带 4.0.0 与 aarch64-linux-android
$ gem --version                         → 4.0.20
$ mvn -v                                → Apache Maven 3.10.0 / Maven home: …/engine/opt/maven
$ pdflatex t.tex                        → Output written on t.pdf (1 page, 11430 bytes)
$ exiftool -ver                         → 13.59
$ gdb --version                         → GNU gdb (GDB) 18.1（< 1 s）
$ go env GOPROXY                        → https://goproxy.cn,direct
```

也就是说这六项在**引擎进程及其子进程**里都是好的。探测当时之所以全红，是因为
执行探测的 shell **没有拿到引擎环境**（`env -i` 式干净环境、或 proot/其它入口）。
这类失败不能靠改代码消除 —— 能做的只有两件事：把真正缺的东西补上；把清单里
「看起来像根因」的描述纠正掉，免得后续排查被它带偏。

> 反证：清单说「LaTeX 的 pdflatex/xelatex/lualatex 二进制全部不存在」「.fmt 数量为 0」。
> 真机事实是 `extensions/texlive/bin/texlive/` 下 446 个入口齐全、`$TEXMFVAR/web2c`
> 里有 5 个 `.fmt`（latex / pdflatex / xelatex / lualatex / tex）。

## 逐条处置

### 1. Ruby —— 无需改动（已验证可用）

`RUBYLIB` 由 `EngineConfig.rubyLibPath()` 扫目录生成（不写死版本号），真机上
`$LOAD_PATH` 10 条、`gem`/`require "json"` 全通。清单里「`$LOAD_PATH` 只有
`engine/lib/ruby`」正是**没有 `RUBYLIB`** 时的形态。

### 2. Maven —— 无需改动（已验证可用）

`PATH` 把 `<root>/opt/maven/bin` 排在最前（缺陷 BN 的修法），`mvn` 的
`dirname "$PRG"/..` 于是解到 `opt/maven`，`boot/plexus-classworlds-2.12.1.jar`
命中。清单描述的 `ClassNotFoundException` 只在「直接跑 `<root>/bin/mvn` 且
PATH 里没有 `opt/`」时出现。

### 3. LaTeX —— 真缺陷：安装期建格式少了 `-interaction=nonstopmode`

- **现象**：全新安装的设备上 `$TEXMFVAR/web2c` 里一个 `.fmt` 都没有，
  `pdflatex t.tex` 报 `I can't find the format file 'pdflatex.fmt'!`。
- **机制**：`tools/fetch-texlive.py` 会把 `language.dat` / `language.def` 收窄到
  闭包里实际存在的断词文件。早期实现是「重新生成文件，只写认出来的条目」，
  于是 `language.def` 只剩 82 字节的一行中文注释 —— 而它的首行
  `%% e-TeX V2.0;2` 是 e-TeX 建格式时的版本探针，`\ifx … \else … \fi` 是控制流。
  头部不符 → `hyphen.cfg` 进交互式 `\@sk {Use fallback?}` 分支 → 我们的 stdin
  不是终端，读到 EOF 直接 `Emergency stop` → `RuntimeInstaller.ensureTexFormats`
  拿到 rc!=0，格式一个都落不了盘。
- **改法（三处，都验过）**：
  1. `tools/fetch-texlive.py`：改成**逐行过滤**，只删「引用了缺失断词文件」的
     条目行；注释、空行、`\ifx`/`\else`/`\fi` 一律原样保留。两个细节是后来
     真机补充的，都不是可选项：
     - `language.def` 的模式名是**裸名**（`\addlanguage {USenglish}{hyphen}{}{2}{3}`，
       没有 `.tex`），TeX 自己补扩展名。只按字面查文件会把这**第一条**判成
       “不存在”而删掉 —— 而它按约定必须是第一条，删了等于把断言打成废纸。
     - `language.dat` 里的 `=alias` 行（`=british`、`=german-x-latest`）是
       **上一条语言条目**的别名。父条目被删了还留别名，等于让 `=german-x-latest`
       去指 english 的断词表 —— 语言用错却不报错，比缺语言难查得多。别名现在
       跟着父条目的去留走。
  2. `RuntimeInstaller.ensureTexFormats`：`-ini` 命令行补
     `-interaction=nonstopmode`。真机 A/B：不给 → rc=1、无 `.fmt`；给了 →
     rc=0、`pdflatex.fmt` 2,264,172 B，随后同一个二进制
     `Output written on t2.pdf (1 page, 11188 bytes)`。
  3. `tools/build-runtime.mjs` 在搬宏包树前断言 `language.def` 的**头部**
     （`%+ e-TeX V…`，上游是两个百分号）与 `\addlanguage` 条数（≥1）。
     原来只断言 `language.dat` 有没有收窄（行数 ≤ 10），所以「`language.def`
     被压成一行注释」这个真正的杀手能一路混进运行时。

  ⚠️ **收窄是原地写进缓存树的**，重跑 `fetch-texlive.py` 会先 `rmtree` 再解包；
  如果树已经被旧逻辑改坏、又因为某种原因没重解，新逻辑只会对着坏文件再收窄
  一次（`language.def` 里已经没有 `\addlanguage` 行，于是收到 0 条）。
  遇到这种情况必须让脚本**真的重解包**（把 `share/texlive/<year>` 改名腾位，
  而不是手工补文件）。

### 4. ExifTool —— 无需改动（已验证可用）

`PERL5LIB` 由 `perlLibPath()` 生成，里面同时包含合并视图与各扩展自己的
`lib/perl5/site_perl/<ver>`（缺陷 BD 的双份设计），`exiftool -ver` → 13.59。

### 5. gdb —— 探测方式问题（`GUILE_*` 未导出）

带 `GUILE_LOAD_PATH` + `GUILE_LOAD_COMPILED_PATH` 时 `gdb --version` 亚秒返回；
**不带**时才是清单里那个「Aborted / 挂死」：libguile 启动要读 `ice-9/boot-9.scm`，
读不到就 abort（缺陷 BA/BC）。清单说「与 PATH、.gdbinit 无关」是对的，但它漏了
这两个变量 —— 它们是 `EngineConfig` 里已有的修复，不在 PATH 里。

### 6. tmux —— 真缺陷：缺 `TMUX_TMPDIR`

- **现象**：`tmux new-session` 报 `no suitable socket path`，而 `tmux -V` 正常。
- **根因**：tmux 只认 `TMUX_TMPDIR`，**完全不看 `TMPDIR`**；Android 上没有 `/tmp`，
  回落到 `/var/tmp` 也不存在。
- **改法**：`EngineConfig` 新增 `tmuxSocketDir()`（`<files>/tmp/tmux`），
  启动时建目录并 `Os.chmod 0700`，环境里给 `TMUX_TMPDIR`。
  为什么要 0700：tmux 对 socket 目录做权限自检，共享的 `<files>/tmp` 是 0771。
- **真机验证**：`tmux new-session -d -s b` → rc=0，`tmux ls` → `b: 1 windows`。

### 7. Go —— 无需改动（已验证可用）

`go env GOPROXY` 在引擎环境里是 `https://goproxy.cn,direct`（`GOSUMDB=off`）。
清单看到的是 `lib/go/go.env` 里的上游默认值，也就是**没走引擎环境**时的值。

### 8. Perl —— 两个真缺陷：cpan 装到死路径、以及 shell 路径编译期写死

清单只点了 `@INC` 里的死路径，真机复验时又挖出**同一族里更狠的一条**。

**(a) 死路径 → 已用 local::lib 兜住**

- **机制**：`@INC` 里那串 `/data/data/com.termux/files/usr/lib/perl5/...` 是编译期
  写死的，而 cpan 默认往 `$Config{sitelib}`（正是其中一条）装 —— 装完 `perl -M`
  仍然找不到。
- **改法**：走 local::lib 那一套 ——
  `PERL_MM_OPT=INSTALL_BASE=$HOME/.perl5`、`PERL_MB_OPT=--install_base …`、
  `PERL_LOCAL_LIB_ROOT`，并把 `$HOME/.perl5/lib/perl5{,/aarch64-android}`
  加到 `PERL5LIB` **最前**（`PERL5LIB` 排在所有内置路径之前，死路径不影响加载）。
  目录不判断存在性：第一次 cpan 跑的时候它还不存在（注释里写了理由）。
- **真机验证**（手写 `Test::KxxyProbe` 走完整 `perl Makefile.PL && make install`）：
  `INSTALL_BASE = …/kxxy-home/.perl5`、`INSTALLSITELIB = $(INSTALL_BASE)/lib/perl5`，
  装完 `perl -MTest::KxxyProbe` 直接命中，`@INC[0]` 就是 `.perl5/lib/perl5`。
  也就是说「装到哪」这条已经闭环，剩下的死路径只是尾部四条无效目录。

**(b) `PL_sh_path` 编译期写死 —— 真机事故，cpan 因此装不了任何模块**

- **症状**：`perl Makefile.PL` 打出
  `Can't exec "/data/data/com.termux/files/usr/bin/sh": No such file or directory`
  然后生成了一份 `PERL = ""` 的 Makefile；`make install` 的第一条命令于是展开成
  裸目录名，报 `sh: 1: /…/perlmod: Permission denied`（错误地把 cwd 当命令执行）。
- **机制**：perl 把 `Configure -Dsh=…` 编进 `PL_sh_path`（在
  `lib/libperl.so` 的 `.rodata` 常量表里，偏移 550029，上下文
  `"…9ABCDEF\0/data/data/com.termux/files/usr/bin/sh\0…"`）。**只有需要 shell
  解析**的形态（带引号、管道、重定向组合）才走
  `execv(PL_sh_path, ["sh","-c",cmd])`，而这条**不回落到 PATH**，
  `$Config{sh}` 也管不到它 —— 我们早已把 Config.pm 的前缀改写成引擎根，
  但那是运行时读的哈希表，与这个 C 字符串无关。真机 A/B：
  `` `echo hi 2>&1` `` 正常（perl 自己 split 后直接 exec），
  `` `"echo" hi 2>&1` `` 恒失败（$? = -1）。
  `ExtUtils::MakeMaker::find_perl()` 偏偏用**带引号**的形态探版本
  （`"$file" -e 'print $]'`），取到空串 → `PERL=""` → 整条 cpan 链路断。
- **改法**：`tools/lib/poolextract.py` 新增 `patch_elf_shell_path()` ——
  把 ELF 里的 `/data/data/com.termux/files/usr/bin/sh`（36 字节）**等长**改写成
  `/system/bin/sh` + 22 个 NUL。总长不变 ⇒ 节偏移/重定位零影响；
  只认「后面紧跟 NUL」的出现位置 ⇒ 不会截断更长的字面量；
  产物不含占位符 ⇒ 不进设备端回填清单。
  选 `/system/bin/sh`（Android 自带 mksh）而不是引擎里的 `bin/sh`：
  引擎根在设备上是变量（`/data/user/<uid>/…`），而 ELF 里的字符串必须构建期定稿。
  影响面：`perl` 与 `exiftool` 两个扩展池条目各带一份 `libperl.so`（含
  `CORE/` 下的副本），重打后四条命中全部清零。

### 9. Python 办公/文档库 —— 真缺陷：一半缺预装、一半缺 pip

清单里的七个库里两类：

| 库 | 有 C 扩展？ | 处置 |
| --- | --- | --- |
| lxml、Pillow、pandas | 有 | Termux 预编译 deb 进**运行时预装**（`python-lxml` / `python-pillow` / `python-pandas`） |
| matplotlib | 有 | Termux 的 `matplotlib` 包（3.11.2，边际闭包只多 qhull / contourpy / kiwisolver 共 5.53 MiB） |
| python-docx、openpyxl、python-pptx、requests | 纯 Python | 新增 `plugins/kxxy-host/lib/pydeps.mjs`，引擎启动时后台 `pip install --user` 补齐 |
| python-dateutil、six、pytz、tzdata | 纯 Python | 同上（pandas 的运行时依赖，Termux 的 pandas deb **没写进 Depends**） |
| packaging、cycler、fonttools、pyparsing | 纯 Python | 同上（matplotlib 的运行时依赖，Termux 的 matplotlib deb **也没带**） |

- 为什么要分开：PyPI 上没有 bionic 的 wheel（manylinux 的 aarch64 轮子是 glibc
  链接，Android 加载器直接拒），lxml/Pillow/pandas/matplotlib 现场编译要
  freetype/qhull 头 + meson/ninja + 完整 NDK，手机上一律失败；反过来纯 Python
  的那几个 Termux 仓库里没有 deb。
- `matplotlib` 为什么必须用 Termux 的包：它把 `_path`/`ft2font`/`_image` 等
  C++ 扩展编好了，PyPI 上同名包只给源码 tarball。装好后由 EngineConfig 钉
  `MPLBACKEND=Agg`（Android 无 Tk/Qt，否则 import 期要连试三个 GUI 后端并刷警告），
  缓存目录指到 `$HOME/.cache/matplotlib`（首次 import 要扫 700+ 字体建
  `fontlist-*.json`，放 tmp 会被系统清掉、每次冷启动重扫）。
- matplotlib 的坑：deb 装上了仍 `ModuleNotFoundError: No module named 'packaging'`
  （`matplotlib/__init__.py:157`）。它的 `Depends` 只写了
  `freetype libc++ libraqm patchelf qhull ninja python python-contourpy
  python-kiwisolver python-numpy python-pillow python-pip`，四个纯 Python 依赖
  （packaging / cycler / fonttools / pyparsing）既不带也不声明，Termux 仓库里也没有 ——
  与 pandas 缺 dateutil 同一个套路。pydeps 补齐后版本升到 `pydeps@3`，
  探针追加 `import matplotlib; use("Agg"); import pyplot`（`use("Agg")` 是必须的，
  默认后端探测在 Android 上会连试 Tk/Qt 并抛 ImportError）。
- pandas 的坑：`import pandas` 在真机上死在
  `ImportError: Unable to import required dependency dateutil` ——
  Termux 的 `python-pandas` 只声明 `libc++, python, python-numpy, python-pip`，
  而 Termux 仓库里**根本没有** dateutil 包。所以 pydeps 的清单里补了
  `python-dateutil`（+`six`）`pytz` `tzdata`，版本升到 `pydeps@2`；
  探针也改成**必须 `import pandas` 成功**才写 `ok` 标记 —— 只探
  docx/openpyxl/pptx/requests 会让 v1 的坏状态被判成 ok，之后再不重跑。
- 为什么装到 **user site**（`$HOME/.local/lib/python3.14/site-packages`）而不是引擎根：
  引擎根是受管资产，塞文件会让运行时的清单指纹校验在下次启动时拒绝安装；
  `$HOME` 是用户资产，重装/升级都不碰。
- 失败策略：没网就当天只试一次（标记文件），绝不阻塞启动。

## 构建期另外踩到的三个坑（都不是清单里的，但不解决就出不了包）

1. **python 被上游推到 3.14.10**，而 `tools/prebuilt/python-android-cp314/` 里那份
   cffi wheel 是拿 3.14.8 的头编的，`build-runtime` 的 `verifyPythonInputs` 于是
   在第一步就报「Python 构件的编译输入已变化」。重编 cffi 需要 NDK + 一个已被
   SHA256 钉死的旧运行时 zip，常规迭代走不通 —— 加 `SEED_VERSION_PINS` 把 python
   停在 3.14.8（补丁级更新，功能零收益，却要赔上整条 ABI 的构建证明）。
2. **上游前端 rc.5 把 boot 审计函数改回同步**（`function IZ(e,t)`，调用点
   `await n.await(),IZ(t,e.modules)` 少了第二个 `await`），而补丁的锚点写死了
   `await ${audit}(…)`，于是在 rc.5 上恒报「未找到锚点」，整条构建链在 `[5/8]`
   就断。现在两种写法各试一次、必须恰好命中一种。
3. **peer 断言的首版判据太严**（v0.9.63 修正）：它把「插件声明的 peer 在闭包里
   找不到」一律当失败，而 `dsh-client-ui-primitives` / `dsh-client-ui-slots`
   在 **0.2.2-rc.3 这份引擎里压根不单独发包**（整份 asar 搜不到，不是被闭包
   裁掉的）—— 同一份引擎 + 同一个插件在真机 0.9.62 上跑得好好的
   （`skipping` 计数 0、移动端 UI 正常）。判据改成：
   - 闭包里**有**的 peer → 版本必须落在区间内（rc.5 那次事故的真信号是
     `dsh-client-locale` 存在且为 0.2.1-rc.5，这一条仍会拦下）；
   - 锚点包 `dsh-client-locale` 必须存在（缺了说明拿错引擎，硬失败）；
   - 其余缺失项只打一行提示，留在构建日志里供事后对照。
