# Codex 对话优先方案落地 · 0.9.40

## 实施范围

将已确认的 A「对话优先」原型落到正式 Codex 侧栏。保留 DSH 0.2.1-rc.5、Codex 0.167.0、现有三协议适配、原生 app-process 运行方式及默认 untrusted 审批。生产界面不使用原型内容或模拟逐字动画。

### 消息输出与折叠

- 用户消息、正文和工具记录保持真实时间顺序，只合并相邻过程项，不把两组工具间的回答移位。
- 合并高频状态刷新，缓存已完成 Markdown；活跃回复直接反映真实增量快照。
- 过程、长正文、代码、命令日志、差异和详情分层折叠，开合按线程/轮次/消息稳定标识保留，切视图与重复通知不重置。
- 上翻暂停跟随，新增内容显示入口；加载更早消息保持锚点。停止保留已输出内容和新草稿。
- 对话运行时只保留紧凑状态及输入条停止；设置/历史提供返回任务和停止，避免重复控制挤占屏幕。
- 单行输入条为“+ / 访问范围 / 模型 / 独立强度 / 发送或停止”；工作模式在 + 菜单明确选择。强度只使用模型声明值，历史显示当时记录，不使用当前选择伪装历史。

### 消息操作

- 用户复制原文、修改并重发；助手复制整轮原始 Markdown、提出修改、重新回答、详情。复制不包含思考摘要、日志或私密 provider 回放，失败提供手动复制回退。
- 编辑前确认，创建所选轮次之前的分支，原历史与实际文件保持不变。首轮创建空白线程；后续原生使用固定 thread/fork 的 inclusive lastTurnId。
- HTTP 重新回答使用已完成工具结果，真实关闭工具，不重跑命令；原生 CLI 无法保证无工具重答，明确禁用并解释。
- 新分支从注册到首次消息接收持有服务端 reservation，普通请求不能抢先发送。统一 send 接收保留幂等账本；请求标识被用于不同文本时拒绝。
- 兼容桥只复制同一模型服务、明确历史前缀白名单覆盖的完整私密回放条目。原生 ID 无法映射 wire ID、缓存已丢失或签名不完整时明确失败，不猜测或复制未来轮次。

### 权限访问

- 请求批准为默认；原生由 CLI untrusted 规则决定审批，不能保证每次写入必弹窗。
- 工作区助手只读同时缩减工具定义和执行层，拒绝 write_file/run_command；原生只读沙箱尚未验证，界面不开放。
- 完全访问必须经过绑定线程、session、模型服务、工作区和连接代次的短期单次 token 确认，不是客户端传 never 即可启用。授权只在内存，不成为全局默认、不继承到分支，重启/重连/模型配置/工作区变化后失效。
- 撤权中断持有 full 的运行任务；发送实际 RPC 前重新验证 transport、generation、工作区、provider/credential revision 和授权代次。旧 never 不能在等待持久化期间重连后泄露到新进程。
- 完全访问仍只是应用普通权限；不提权、不关闭 SELinux、不声称存在工作区内核沙箱。HTTP 路径、凭据文件、大小和超时保护仍有效。

### 文件变更和撤销

- 受控 HTTP write_file 在私有 codex-change-journal 记录前像、后摘要、文件身份和状态，默认最多256项/8 MiB。日志满或损坏时拒绝新的受控写入，不静默丢弃撤销证据。
- 撤销先检查整轮全部目标，确认后逐文件重复核对 canonical 路径、hash、inode/dev/mode等身份，原文件恢复或删除本轮新增文件。
- 后续编辑、链接替换、跨轮覆盖和证据不完整时拒绝覆盖；执行期间失败明确 partial 与成功文件，不宣称原子事务。
- 旧历史、原生修改、命令任意变化没有受控前像，不提供自动撤销。普通文件系统检查与 rename 间仍有外部竞态边界。
- 日志是应用私有明文数据，前像不进入页面或模型；凭据路径及日志目录均被文件工具屏蔽。
