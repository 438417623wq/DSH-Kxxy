`127.0.0.1:3080`，等于这层门从来没关上。修一处判定 + 补一层脱敏 + 给写操作加 CSRF 语义，
三条一起解决。

- **真 bug，能修**：yarn 链接（4）、字体默认族（6）、git 身份（7）、pip 镜像（8）。

## 1.（P0）鉴权判定用错了服务 —— 一条修好 1/2/3

### 已核实的根因

`plugins/kxxy-host/lib/index.js:229`

```js
function isTrustedRequest(ctx, req) {
  try {
    const auth = ctx.get('authorization')
    if (auth && typeof auth.isTrustedRequest === 'function') {
      return auth.isTrustedRequest(req)      // ← 这个分支永远不成立
    }
  } catch {}
  const host = String(req.headers?.host ?? '')
  return host.startsWith('127.0.0.1:') || host.startsWith('localhost:')   // ← 恒真
}
```

`@deepseek-ai/dsh-authorization` 的真实语义（0.2.1-rc.5，读源码确认）是
**凭证获取流程的注册表**（OAuth 式「打开这个页面、贴那个码」），
导出只有 `AuthorizationService` / `AuthorizationError` / `AuthorizationDeclinedError`，
**没有任何请求级判定方法**。所以兜底分支是唯一被执行的分支。

而真正的判定入口在另一个包：

```js
// @deepseek-ai/dsh-client-connection —— service 名是 "connection"
isAuthenticated(request, secure = false)     // 校验 authority 绑定的签名 cookie
authenticateApi(request, secure = false)     // 只认 API 凭证，不发操作者
authenticatedUrl(baseUrl)                    // 把 launch token 拼进 URL（dsh-remote-link 已在用）
```

cookie 语义（同文件）：`encodeCookie({version, authority, issuedAt, expiresAt}, secret)`，
**authority = Host**。所以「127.0.0.1:3080 的 cookie 拿去访问 192.168.1.23:8765 无效」——
这正是当初写注释时想表达的意思，但写错了对象。

顺带确认：`webServer.register()` 对路由**不做任何鉴权**（`dsh-host-webserver` 里
`isAuthenticated` 出现 0 次）。官方 `/api/*` 的 401 来自连接层的中间件，插件自己
`register` 的路由不在那条链上 —— 所以这不是"插件越权"，而是"插件必须自己守门，而我们守错了"。

### 改法

```js
function isTrustedRequest(ctx, req, secure) {
  const conn = ctx.get('connection')
  if (conn && typeof conn.isAuthenticated === 'function') {
    return conn.isAuthenticated(req, secure === true)   // 正规入口
  }
  return 'unavailable'                                  // 不让缺失变成放行
}
```

三层处理，**失败方向必须是关**：

| 判定结果 | 页面 / 静态资源 | `/kxxy/api/*`、`/kxxy/media` |
|---|---|---|
| `true` | 正常 | 正常 |
| `false` | 200 返回一个「请从 DSH 打开的链接进入」静态页 | 401 JSON `{error:'unauthorized'}` |
| `'unavailable'`（服务改名/缺失） | 200 静态页，页面顶部红条「鉴权服务不可用」 | 503 JSON `{error:'auth-unavailable'}` |

为什么要给静态页留一条缝：页面是纯静态 HTML/JS/CSS，不含状态；留缝的作用是让用户
**看到一句人话**，而不是一个光秃秃的 401 白屏（现在的 v0.9.16 引导卡就是为了不再出现
「打不开也不知道为什么」）。API 一律不给缝。

### 会破坏什么（必须验）

远程链路（`dsh-remote-link/lib/connector.js`）是这么转发的：

```
手机 → 8765（配对 cookie 门）→ 转发到 127.0.0.1:3080，host 改写为 127.0.0.1:3080，
                             并注入它用 launch token 换来的上游会话 cookie
```

也就是**到 kxxy-host 眼里，远程请求和本机浏览器请求长得一样**（Host 一致、cookie 有效），
所以换成 `isAuthenticated` 不会误伤远程。这一条要在真机上验，不能只看代码。

### 验收

1. `curl -sv http://127.0.0.1:3080/kxxy/api/state`（不带 cookie）→ **401**。
2. `curl -sv -H 'Host: evil.example' ...` → 403/401（原来就是 403，别退化）。
3. 手机 App 打开控制台 → 页面正常、数据正常（有 cookie）。
4. 手机走 8765 远程 → 页面与数据正常（连接器注入 cookie）。
5. 桌面浏览器用 DSH 打印的 `?token=` 链接进过一次后再开 `/kxxy` → 正常。
6. 契约测试：`tools/smoke-plugin.mjs` 的 mock ctx 里塞一个 `connection.isAuthenticated`
   桩（固定返回 false），断言 `/kxxy/api/state` = 401；再塞返回 true 的桩，断言 200。

## 2.（P0）日志接口原样吐 token

### 已核实的根因

`plugins/kxxy-host/lib/index.js:1451`

```js
const all = readFileSync(logFile, 'utf8')
tail = all.slice(-64 * 1024)          // 原样
sendJson(res, 200, { tail })          // 原样
```

而 `engine.log` 里必然有 `dsh web: http://127.0.0.1:3080/?token=…`（上游启动时打的），
一读就是当前有效的凭证。

### 改法

**不是「加个正则」，是把「回什么」定成白名单口径。**

1. 脱敏函数 `redactLog(text)`，按顺序替换（顺序有意义，先长后短）：

| 目标 | 规则 | 替换成 |
|---|---|---|
| URL 里的 token/code/key/secret | `([?&](token\|code\|key\|secret\|password)=)[^&\s"'<>]+` | `$1***` |
| Authorization 头 | `(?i)(authorization:\s*bearer\s+)\S+` | `$1***` |
| Cookie 头 | `(?i)(cookie:\s*).+` | `$1***` |
| 常见 API key 形状 | `sk-[A-Za-z0-9_-]{16,}` | `sk-***` |
| 配对码 | `/__kxxy_pair\?code=[0-9a-f]{8}` | `…?code=***` |
| 家目录绝对路径 | `^/data/user/0/app\.kxxy/files/home` | `~` |

2. 只回**尾部 32 KB 且按行切齐**（不切断半行），`cache-control: no-store` 已有。
3. 响应里带 `redacted: true, lines: n`，前端脚注说明「已脱敏」，免得用户以为日志丢了东西。
4. **不做**：去改 `engine.log` 本身。上游每次启动都会再写一行 token，追着擦是徒劳，
   而且文件在 app 私有目录（同 uid 才能读），真正的暴露面是「这个 HTTP 接口」，修接口即可。
   这一点要写进文档，避免以后有人以为"日志已经干净了"。

### 验收

- 起一个含 `?token=abcdef` 的假 `engine.log`，打接口，断言响应里 `abcdef` 不出现、
  `token=***` 出现、行数与原文一致。
- 真机：`/kxxy/api/log` 返回 12 KB 里 grep `token=` 只剩 `token=***`。

## 3.（P0）写操作：鉴权 + CSRF 语义

### 已核实的根因

与第 1 条同一处 `isTrustedRequest`。审计里「`extensions/install` 返回 409、
`plugins/toggle` 返回 400」是**处理函数执行到参数校验**才报的错，说明门是开着的。
这些 handler 内部没有二次校验。

### 改法

1. 统一门：`/kxxy/api/*` 全部走第 1 条的判定（现在只有 prefix 顶部一次，保留），
   **并**在 `dispatchAction` 入口再判一次（防止将来有人新注册一条 `/kxxy/api2` 忘了守）。
2. 写操作（`POST`）追加两条轻量 CSRF 语义，成本低、误伤小：
   - 要求 `content-type: application/json`（表单跨站提交带不了这个头而不触发预检）；
   - 若带 `sec-fetch-site`，必须是 `same-origin` / `none`（`cross-site` 直接 403，
     现有 smoke 测试里已有这条，扩到所有 POST）。
3. 破坏性动作（卸载扩展、删除设备、恢复默认）加一次性 nonce：页面加载时由
   `/kxxy/api/state` 下发 `csrfToken`（进程内随机，随会话轮换），POST 必须回带。
   这一步可以放到 v0.9.19，先做 1、2。

### 验收

- 无 cookie POST `/kxxy/api/action` → 401。
- 有 cookie 但 `content-type: text/plain` → 415。
- 有 cookie 但 `sec-fetch-site: cross-site` → 403。
- 正常页面点「安装扩展 / 启停插件」→ 仍按原逻辑工作（不能被门挡死）。

## 4.（P1）yarn 命令损坏：bin 与 share 分离

### 已核实的现象

`extensions/yarn/bin/yarn` 是个 shell wrapper，内部按**自身目录**找 `yarn.js`：

```sh
basedir=$(dirname "$(readlink -f "$0")")
exec node "$basedir/yarn.js" "$@"
```

而真实入口在 `extensions/yarn/share/yarn/bin/yarn.js`（`readlink -f` 解析到 wrapper
所在目录后，同目录没有 `yarn.js`）。

### 改法（两条，先通用后特例）

1. **通用规则**：链接完 `bin/*` 后做一次「wrapper 体检」——读 wrapper 文本，抽出对
   `$basedir/<file>` 的引用，若该文件不存在，就在**包目录内**按文件名找唯一命中，
   在 wrapper 旁边补一条相对软链（`bin/yarn.js → ../share/yarn/bin/yarn.js`）。
   找不到或有多个命中就跳过并记一条 warn，不猜。
2. **特例兜底**：`yarn` 包额外检查 `share/yarn/bin/yarn.js` 是否存在，存在即建链。
   特例只写一条，不铺开成"每个包一张表"。
3. 顺手把 `corepack` 那四个入口的自愈逻辑（`RuntimeInstaller` 里已有）复用一份判断，
   避免 `corepack enable/disable` 之后又坏回去。

### 验收

`yarn --version` → `1.22.22`；`pnpm --version`、`npm --version`、`npx --version` 各自正常；
装一个带 `bin` 的扩展后，其命令可直接执行。

## 5.（P2）node-gyp 缺 NDK：**不修，改成准确报错**

`gyp: Undefined variable android_ndk_path` 的实质是：Termux 的 node 是
`android/arm64` 目标，node-gyp 在 android 平台**必须**有 NDK 才能定位 sysroot 与
clang 工具链；运行时只带编译链，没有 NDK 目录。

三条路都不划算：

- 打进 NDK：解压后 3–4 GB，包体积翻倍，且只服务极少数包。
- 假装能编：改 `android_ndk_path` 指向一个假目录 → 链接期报更费解的错。
- 走 `--nodedir` 用 linux 头文件 → ABI 不匹配，装上就崩。

**方案**：检测 + 指路 + 兜底。

1. `kxxy` 运行时给 npm 加默认 `--build-from-source=false`（优先预编译产物）。
2. 失败时把 node-gyp 的原始报错换成人话，并在控制台「诊断」卡里给三条出路：
   ① 换带预编译二进制的版本；② `npm i --ignore-scripts`（纯 JS 包）；③ 自备 NDK 并在
   设置里填路径（填了才透传 `android_ndk_path`）。
3. 文档里明写「需要现场编译 C++ 的包在 Android 上大概率装不上」，别让人反复试。

## 6.（P1）默认字体不含中文：别名不够，得改默认解析

### 已核实的根因

`RuntimeInstaller.ensureFontConfig()` 生成的 `kxxy-fonts.conf` 只写了：

```xml
<alias binding="same"><family>sans-serif</family><accept><family>Noto Sans SC</family></accept></alias>
<alias binding="same"><family>sans-serif</family><accept><family>NotoSansSC-Regular</family></accept></alias>
```

只覆盖了 `sans-serif` 这个**族名**。两个工具都不问 `sans-serif`：

- ImageMagick 的默认字体来自它自己的 type 配置（实测解析到 `AndroidClock`，
  `-list font` 首项），根本不查 fontconfig 的族别名；
- ffmpeg `drawtext` 走 fontconfig，但默认族是 `Sans`（→ DejaVu 系）。

缺字形时两者都**不报错**，一个出白图、一个出 `D0D00`。

### 改法

1. fontconfig 侧补齐常见默认族名（`Sans`、`Sans Serif`、`DejaVu Sans`、`Helvetica`、
   `Arial`、`sans`）：`<alias binding="same">` + `<prefer>`（不是 `accept`，`prefer` 才改首选）。
2. ImageMagick 侧给一份自己的 `type.xml`，把 `NotoSansSC-Regular.ttf` 注册成
   `Sans` / `Sans-Serif` / `Arial`，并通过 `MAGICK_CONFIGURE_PATH=<root>/etc/ImageMagick-7`
   优先加载（`type.xml` 首项顺序决定默认解析）。
3. 两条都做完要**实测校准**：`magick -list font | head -1`、`magick -annotate` 中文出图、
   `ffmpeg drawtext` 中文，三者都过才算完。
4. 若 IM 仍不吃 fontconfig（版本差异），退回方案 B：`<root>/bin/magick` 与 `convert`
   加一层薄 wrapper，命令行**没有** `-font`/`-family` 时注入 `-font <NotoSansSC 绝对路径>`。
   wrapper 只做这一件事，不改其他参数。方案 B 要在文档里标注"这是兜底，不是正解"。

## 7.（P1）git 无默认身份

1. 安装/首次启动时写 `$HOME/.gitconfig`（存在则不覆盖）：

```ini
[user]
    name = Kxxy User
    email = kxxy@localhost
[init]
    defaultBranch = main
[safe]
    directory = *
[core]
    autocrlf = false
```

`safe.directory = *` 是必要的：扩展目录与用户项目目录属主/路径经常变，不加会一路
`dubious ownership`。

2. SSH：**不静默生成**。控制台「远程与 Git」卡里放一个「生成 SSH 密钥」按钮，
   点了才 `ssh-keygen -t ed25519 -N '' -C "kxxy@<model>"`，生成后把**公钥**显示出来
   供复制（私钥永不显示）。顺带写 `known_hosts`（`ssh-keyscan github.com`，失败不阻塞）。
3. 首次 `git commit` 前若检测到没有 identity，在页面上给一次提示而不是让它报英文错。

## 8.（P1）pip 未配置镜像

镜像目前只做了 npm 半边（`EngineConfig.kt:951` `NPM_CONFIG_REGISTRY`）。

补三处，优先级从高到低：

1. `$HOME/.config/pip/pip.conf`（用户级，最稳）：
```ini
[global]
index-url = https://pypi.tuna.tsinghua.edu.cn/simple
trusted-host = pypi.tuna.tsinghua.edu.cn
timeout = 30
```
2. 环境变量 `PIP_INDEX_URL` / `PIP_TRUSTED_HOST`（进程级，覆盖一切）。
3. `<root>/etc/pip.conf`（全局，最后兜底）。

**可配**：控制台「包管理器镜像」卡加一个切换（官方源 / 清华 / 阿里），写进
`$HOME/.config/pip/pip.conf` 并热更新环境变量；已有 `mirror.mjs` 可以复用它的状态与
健康检查，不要另起一套。

**不做**：把镜像写死在 APK 里且不给关。企业内网/代理环境下硬编码镜像会直接把人卡住。

## 9.（P2）`/tmp` 不可写：已经是边界，只补说明

`RuntimeInstaller.ensureTmpDir()` 已经在做事：`/` 可写就建 `/tmp → $TMPDIR` 软链，
不可写就静默跳过；`TMPDIR` / `TMP` / `TEMP` / `GOTMPDIR` 都已指向 `files/tmp`。

Android 上 `/tmp` 属 `shell:shell 771`，app uid 不在 shell 组，**无 root 无法改**。

所以只做两件事：

1. `XDG_RUNTIME_DIR` 也指向 `files/tmp`（有些脚本认这个）。
2. 文档与「诊断」卡明写：硬编码 `/tmp` 的第三方脚本会失败，这是平台限制；
   让脚本改用 `$TMPDIR`/`mktemp`。

## 10.（P2）`raw.githubusercontent.com` 被解析到 0.0.0.0

现象与证据都指向**DNS 层单域名拦截**（hosts 干净、同域其他 GitHub 域名正常）。

App 侧能做的只有"绕"，不能"修 DNS"。三层：

1. **诊断**：运行时 `dns.lookup('raw.githubusercontent.com')` 返回 `0.0.0.0` 时，
   在控制台显示一条明确提示（而不是让 git/npm 报 `Could not resolve host`）。
2. **git 兜底改写**（可关，默认关，检测到污染时提示开启）：
```ini
[url "https://gh-proxy.com/https://raw.githubusercontent.com/"]
    insteadOf = https://raw.githubusercontent.com/
```
   多个候选镜像做健康检查后择一，写进 `$HOME/.gitconfig`；关掉就删掉这段。
3. **文档**：告诉用户这多半是运营商/网络侧 DNS 污染，换网络或开系统「私人 DNS」
   （DoT）通常能解；App 没有权限改系统 DNS。

**不做**：在引擎里塞一个 DoH 解析器替换 Node 的默认 `lookup`。能做，但要接管所有
`net`/`tls`/`undici` 连接，收益（省一次手动改配置）远小于风险（HTTPS 证书校验、
HTTP/2、连接复用全都可能被搅坏）。

## 11. 排期与验收

**v0.9.18（安全 + 两个确定的 bug）**：1、2、3、4、6、7、8。
安全三条是同一个入口，一起改一起测；4/6/7/8 都是"配置/链接"级别，改动面小。

## 12. 明确不做的事

- 不改 `engine.log` 写入行为（上游每次启动都打 token，擦了也会再写；修读取侧即可）。
- 不随包发 NDK（3–4 GB，只服务极少数包）。
- 不用 DoH 替换 Node 默认解析（风险大于收益）。
- 不静默生成 SSH 私钥（要么用户点，要么不做）。
- 不把 `/tmp` 用 proot/bind-mount 硬掰（要 root，且会把引擎环境搞得更不可预测）。
