# v0.9.77：一个 Python 环境 + 无 PMU 时的可用采样 + 显式快照去重

承接 v0.9.76 的三条实测反馈。本轮不再解释「为什么不行」，而是把每条都落到
**能跑出结果的路径**上；确实做不到的那一点（f2fs 硬链接）给出可量化的替代。

## 1. Python：默认 `python3` 一个环境装下全部包

**问题**：默认 `python3` 被路由到 glibc 3.12（numpy/scipy/sklearn/cv2，缺 pandas/torch），
原生 3.14 反过来（pandas/torch 有，sklearn/cv2 无），两个解释器各缺一半。

**处置**：把 glibc 3.12 补成全集，让它成为唯一的默认环境。

```sh
kxxy-glibc-provision python-full     # ml + pandas + torch，幂等
```

| 目标 | 内容 | 体积 |
| --- | --- | --- |
| `python-ml` | numpy / scikit-learn / opencv-python-headless | ~120 MiB |
| `python-data` | pandas | ~12 MiB 下载（解出 ~70 MiB） |
| `python-torch` | torch（cp312 manylinux aarch64） | 485 MiB 下载 |
| `python-full` | 以上三者，末尾打印六个包版本 | — |

每个目标独立标记（`<files>/glibc/.provisioned/`），torch 失败不会拖累 pandas；
已有的 `python-ml` 标记不会再挡住新包 —— 进入前先 `import` 实测。

**坑（真机实测）**：PyPI 上 `torch` 2.15 的 linux aarch64 轮子是 **CUDA 链接版**
（484 MiB），装进去 `import torch` 直接 `OSError: libcudart.so.13`，随后被
`_preload_cuda_deps` 误报成 `libcublasLt.so.*[0-9] not found`。
官方 CPU 索引的**同名**轮子才是纯 CPU（171 MiB，`torch.version.cuda is None`）：

```sh
kxxy-glibc -c 'pip install -i https://download.pytorch.org/whl/cpu torch'
```

`prov_torch` 已默认走该索引（可用 `KXXY_PIP_TORCH_INDEX` 覆盖）。
另一个坑：`pip uninstall torch` 不加 `--break-system-packages` 会静默失败，
于是"装 CPU 版"实际没装、旧 CUDA 版还在。

**网络**：PyPI 直连 484 MiB 会反复超时重试（实测多次从头开始）。
`kxxy-glibc-provision` 支持 `KXXY_PIP_INDEX` 换镜像；镜像也超时时走
`adb push /data/local/tmp → run-as cp files/ → pip install --no-index`
（`/data/local/tmp` 是 0771 shell:shell，app 能按精确路径读，不能列目录）。

**边界**：bionic 原生 3.14 仍装不了 sklearn/cv2（无 Android 轮子，manylinux 产物
卡 `ld-linux-aarch64.so.1` 命名空间）。`python3.14` 保留给确实需要新解释器的人，
`_kxxy_hint.py` 的提示改成直接指向默认 `python3`，并说明三个解释器各自有什么。

## 2. perf：PMU 被策略拒绝时改为「不需要 PMU」的采样

**问题**：应用域（`u:r:untrusted_app_27`）`perf_event_open` 返回 EACCES，
`perf stat` / `perf record` 一律 exit 1。上一版只给了「去 adb run-as 跑」的提示。

**关键认知**：统计与采样本身不依赖 PMU。于是加了两条降级路径，都不越过任何权限检查：

| 子命令 | 正常路径 | 降级路径 | 降级输出 |
| --- | --- | --- | --- |
| `perf stat` | perf_event_open 计数器 | `wait4` rusage / `/proc/PID/stat` 增量 | task-clock、page-faults、context-switches、CPU 利用率 |
| `perf record` | mmap 环形缓冲 | `ptrace(PTRACE_TRACEME)` + SIGSTOP 定时抓 PC | 与 PMU 路径**同一份** perf.data 文本格式 |

- 判定入口 `KXXY_PERF_MODE=auto|pmu|fallback`（默认 auto：先试 PMU，一个都没开起来才降级）。
- `ptrace` 采样封顶 200 Hz（每样本一次 STOP/CONT 往返，再高会明显拖慢目标）；
  只采主线程，没有调用链 —— 输出里如实标注。
- 降级产物 `#mode ptrace-fallback`，`perf report` 直接在表头显示模式，符号化逻辑复用。

真机实测（runas 域，强制 fallback 以验证代码路径）：

```
perf record -F 100 -- python -c '<4e6 次乘加>'
→ 92 个样本 / 1.06 s / 11 个映射
report: PyDict_New 17.4% · PyObject_Free 16.3% · _PyEval_EvalFrameDefault 9.8%
```

**坑**：exec 停下的时刻动态库还没加载完，此时抓的 maps 只有主程序/vdso/linker64，
样本全落不进模块 → 报表全是 `[unknown]`。修法是采样中按需刷新 maps（0.2 s 节流）。

## 3. 硬链接：仍是设备策略（已定性），但快照去重可用了

`link(2)` / `linkat` / `FICLONE` 在 `files/`、`cache/` 恒 EACCES，与域无关
（`u:r:shell:s0` 同样），用户态无解。本轮补了一条容易误导的观察：
**glibc 容器里 `os.link` 会「成功」**，那是 proot `--link2symlink` 把硬链接模拟成
符号链接 —— `stat` 跟随链接看到同 inode，f2fs 上并没有硬链接。不要用它判断能力。

真正能做的是「空间去重」，做成显式 opt-in：

```sh
KXXY_RSYNC_DEDUP=symlink kxxy-rsync -a /src/ /snap-2/ --link-dest ../snap-1
```

- 只在 `--link-dest` **探针失败**、且**不带 `-n`**、且**原生 rsync 返回 0** 之后执行；
- 只处理两侧都已存在的普通文件（大小 + mtime 走 rsync 自己的 quick-check，
  `KXXY_RSYNC_DEDUP_VERIFY=1` 再逐字节比对），因此不会复活已删除/被排除的条目；
- 真机实测：基准 304 KiB → 副本 304 KiB vs 去重后 4 KiB，`cmp` 内容一致；
  `stat -L`（跟随链接）两侧 inode 相同，`lstat` 能看到是软链。

代价写在输出里：删掉基准快照会让这些文件变断链。默认行为不变（老实打印
「capability unsupported」后原样执行 rsync），不静默改语义。

## 4. 契约变更

- `PATCHSET_MARKER` `kxxy-patchset@34` → `@35`（三处同步）。
- glibc 扩展版本 `24.04.3-r2` → `r3`（provision 脚本内容变了，需重装扩展才生效）。
- `KXXY_RSYNC_LINK_MODE=symlink` 仍禁用，错误信息改为指向 `KXXY_RSYNC_DEDUP`。
- 测试：`test-perf.py` 20 例（新增 7 例降级/边界）、`test-kxxy-rsync.py` 31 例
  （新增 6 例去重）、`test-hardlink-wrappers.mjs` 契约改为「默认 exec-only + 显式门控」。

## 5. 真机验收（Redmi K60 Pro，@35）

| 项 | 命令 | 结果 |
| --- | --- | --- |
| 单环境六包 | `python3 files/kv1.py` | numpy 2.5.5 / scipy 1.18.1 / sklearn 1.9.1 / cv2 5.1.0 / pandas 3.1.1 / torch 2.15.0+cpu；matmul=32768 |
| perf stat（PMU） | `perf stat -- true` | 23,264,473 cycles，rc=0 |
| perf stat（降级） | `KXXY_PERF_MODE=fallback …` | 276.235 ms task-clock / 1,555 缺页 / 8 切换，rc=0 |
| perf record+report（降级） | `KXXY_PERF_MODE=fallback …` | 66 样本，PyObject_Free 22.7% / PyDict_New 13.6% |
| rsync 默认 | `--link-dest` | 448 KiB 复制 + 诚实警告，rc=0 |
| rsync 去重 | `KXXY_RSYNC_DEDUP=symlink` | 4 KiB，`stat -L` 同 inode，`cmp` 一致 |
| rsync dry-run | `-n` + 去重 | 不建目录、不改造 |
| ln | `ln a b` | `Permission denied`，rc=1，目标不生成 |
| provision | `python-full` | 六包版本行一次打印 |
