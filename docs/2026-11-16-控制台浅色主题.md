# 控制台浅色主题整页发黑（0.9.57 → 0.9.58）

## 现象

系统切到浅色、控制台外观也选「浅色」时，`/kxxy` 管理页整体是深色底、浅色字，
只有顶栏是浅色半透明底 —— 于是顶栏变成**白底白字**（「DSH Kxxy 控制台 / 对话 /
引擎正常」几乎看不见）。深色主题下一切正常，所以一度被当成「浅色只是没做完」。

## 定位

三步就把范围缩到一份文件：

1. **计算值先对上症状**。无头 Edge + CDP 读 `getComputedStyle`，浅色下
   `body` 的 `background-color` 是 `rgb(21, 21, 23)`（`#151517`），
   `color` 是 `rgb(249, 250, 251)`，而 `.app-header` 的背景是
   `rgba(249, 250, 251, 0.86)` —— 深色底 + 浅色字 + 浅色顶栏，正是「白底白字」。
2. **变量层再对一次**。`--bg-base` 的值被解析成 `#151517`，那是 `host.css`
   里 `var(--dsw-alias-bg-base, #151517)` 的**第二参**；同时
   `getPropertyValue('--dsw-alias-bg-base')` 返回空串。空串意味着「变量有引用
   但值无效」，不是「变量没定义」。
3. **回到源头**。`plugins/kxxy-host/web/theme.css` 里有两行是这样的：

   ```
   L6  `;var design_platform_css_default=`body{--dsw-static-amber-100:#fef5e7;…}
   L10 `;var onboarding_css_default=`body{--dsw-alias-onboarding-accent:#3964fe;…}
   ```

   浏览器解析到反引号，把**整条规则**丢弃。被丢的恰好是浅色那套
   `body{--dsw-static-*}`：alias 层虽然还在，但它的值是
   `var(--dsw-static-neutral-bluish-00)`，被引用的 static 没了，整串 var()
   在计算值阶段失效 → `host.css` 的兜底生效 → 全站深色。

   深色主题另有 `body[data-ds-dark-theme]` 一套**字面量**值，不依赖那层 static，
   所以看起来毫无问题。这就是「深色没事、浅色全黑」的全部原因。

## 根因

`tools/build-runtime.mjs` 的 `extractOfficialTheme()` 用「配对双引号」正则
（`/"((?:[^"\\]|\\.)*)"/g`）去上游模块里捞 CSS 片段。而上游
`dsh-client-ui-theme/lib/client.js` 把 CSS 放在**模板字面量**（反引号）里，
代码里另有双引号 —— 于是正则把「引号 A … 引号 B」之间整段代码当成一个字符串
抓走，产出的 CSS 里混进了模板字面量的收尾和下一段 JS 的赋值。

同一份产物里 `--dsw-alias-bg-base` 出现 2 次、`--dsw-static-neutral-bluish-00`
也出现 2 次，但其中**浅色的那一条整块无效**，所以静态看「文件里明明有」，
只有在浏览器里求值才暴露。

## 修复

### 1. 抽取器重写（`tools/lib/theme-css.mjs`）

- 正经扫字符串字面量：双引号 / 单引号 / 反引号；跳过 `//`、`/* */` 注释与
  正则字面量；模板插值 `${…}` 递归跳过（含嵌套模板与对象字面量）——
  上游的插值里嵌着整张翻译表，只数花括号会在字符串里的 `}` 上提前收工。
- 选择器白名单：只接受 `html` / `body` / `body[属性]` 形态，非 CSS 文本再也进不来。
- `assertThemeCss()` 自检：反引号、`var x=`、模板占位符、关键 token 缺失、
  深色块缺失、**`var(--dsw-*)` 引用未定义** —— 任一条命中就让构建失败。
  最后那条正是本次事故的直接判据。

### 2. 接线（`tools/build-runtime.mjs`）

`extractOfficialTheme()` 改为调用上面的模块，失败即 `throw`（不再「跳过生成」
继续用旧文件）。

### 3. 兜底本身也要分深浅色（`plugins/kxxy-host/web/host.css`）

原来 17 个 `var(--dsw-…, #深色兜底)` 的第二参只有深色值，一旦 token 再丢，
浅色还是会整页回落。现在先定义一层 `--fb-*`（浅色在 `body`、深色在
`body[data-ds-dark-theme]`），映射改成 `var(--dsw-…, var(--fb-…))`。

顺带把四处写死的白色（`.icon-button:active`、`.badge-subtle`、
`.button-subtle:active`、`.info-row` 的下边框）改走 `--bg-hover` /
`--border-subtle` —— 浅色下 `rgba(255,255,255,.05)` 等于没有。

### 4. 装机死角：载荷不适配时降级全量（`RuntimeInstaller.kt`）

0.9.57 装机踩到的 `PythonRuntimeRepair$Refused: 不适用此增量修复：设备宿主指纹
不匹配基线或目标` 是同一类问题的另一面：只要插件改过，`python-repair` 载荷的
`baseHostFingerprint` 与 `hostFingerprint` 都指向新指纹，而设备上还是上一版 →
`preflight()` 直接抛 `Refused`，`install()` 再也走不到全量分支，只能手工进
「诊断/救援 → 离线修复运行时」。

现在把「不适用」与其它拒绝分开：

- `PythonRuntimeRepair.NotApplicable` / `DshRuntimeUpgrade.NotApplicable`
  （`Refused` 的子类），只在「宿主指纹既非基线也非目标」时抛；
- `install()` 捕到它们就置 `incrementalSkipped`，跳过 `isComplete()` 快路径与
  「增量锚点未就绪」的硬拒绝，**改走全量安装**（只替换 zip 里的顶层目录，
  `extensions/` 与用户数据不动，约 90 秒）；
- 用户文件冲突、校验失败**仍然是 `Refused`**，一条边界都没放宽。

注意这条修复与本轮改 CSS 是互补的：`python-repair` 载荷只带
`lib/node_modules/kxxy-host/` 下的 `lib/index.js`、`lib/*.mjs`、`web/host.js`、
`web/index.html`、`lib/.fingerprint` —— **不含 `web/host.css` 与 `web/theme.css`**。
只靠增量修复，设备上的 `.fingerprint` 会升级而样式表还是旧的，等于「报着新指纹
跑旧样式」。所以样式改动必须走全量。

## 验证

- `node tools/test-theme-css.mjs`：18 项全过。含「事故产物必须被自检拒收」与
  「真实 asar 抽取」两条。
- `node tools/test-remote.mjs`：266 项全过（界面状态无关回归）。
- 无头 Edge（412×915 @2x）逐页截图：浅色下 `body` 为 `#fff`、字 `#0f1115`、
  卡片 `#fff` + 1px `rgba(0,0,0,.04)` 边框，顶栏 `rgba(249,250,251,.86)`；
  深色与 0.9.57 观感一致（`#151517` / `#1b1b1c`）。
- 真机（Redmi K60 Pro）安装后控制台浅色正常，见提交说明。

## 复用要点

- **从编译产物里抽 CSS，不能按引号配对**。要么读包里的 `src/styles/*.css`
  （本次上游有：`design-platform.css` / `onboarding.css`），要么老老实实扫字面量。
- **生成物要有自检，且自检要检查「引用闭合」**。只检查「关键 token 在不在」会漏，
  因为坏掉的是被引用的那一层。
- **兜底值本身是主题的一部分**。深色兜底 + 浅色主题 = 事故。
- **增量载荷不适配需要有出口**，否则「插件一改 = 装机失败」会周期性复发。
