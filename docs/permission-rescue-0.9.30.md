# 0.9.30：Root 切回普通模式后的权限修复

## 已定位的故障

用户确认曾以 Root 模式使用，之后切回普通模式。0.9.29 日志反复显示：

- `.credentials.yaml`：EACCES，凭据插件无法启动。
- `storages/workspace.json`：EACCES，工作区插件无法读取记录。

凭据服务是连接服务的依赖，所以控制台也打不开。这类问题不能靠重装运行时或 L3 重建插件依赖修好。

## 操作方法

1. 覆盖安装 `Kxxy-0.9.30.apk`，不要卸载，不要清除应用数据。
2. 启动页选择 **诊断/救援 → 修复用户数据权限**。
3. 确认停止引擎并检查权限。此步骤不请求 Root。
4. 若提示文件归其他属主，会弹出第二个 **用 Root 恢复应用文件属主** 确认框。
5. 确认这次 Root 修复，并在手机的 Root 管理器中允许授权。
6. 修复验证完成后重新启动。若仍失败，保存新的脱敏日志；日志包括 uid/gid、文件权限及可取得的安全标签，不包含凭据内容。

## 保护范围

- 仅处理日志点名的两个私密文件及必要父目录，恢复给应用 uid/gid。
- 不递归修改整个 home，不跟随公开工作区或会话软链。
- 不读取、重写、删除、移动或重建凭据和工作区记录内容。
- 私密文件保持 0600，必要目录保持应用私有访问，不使用 chmod 777，不关闭 SELinux。
- Root 是单次明确授权的修复能力，不改变以后启动时的运行模式。
- 只保存修改前后元数据和结果，不把旧 root 属主作为一键撤销目标，以免再次让普通模式不可用。

## 验证限制

主机 Kotlin/Node 测试和签名校验不能代替失败手机的 Root 实现/SELinux 验证。最终以手机覆盖安装后实际启动成功为准；失败时不要清数据，请提供新的权限诊断日志。
