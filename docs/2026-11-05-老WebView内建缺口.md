# 老 WebView 的内建缺口：`signal?.throwIfAborted is not a function`

> 2026-11-05 · 对应版本 0.9.12
> 现场：黑鲨5 Pro（SHARK KTUS-A0 / JOYUI 13 / 骁龙 8 Gen 1）。界面能点、会话
> 列表能看，但**所有要靠 client API 的面板全红**：
>
> ```
> client api: agentPresets/list failed: signal?.throwIfAborted is not a function
> 加载提供商目录失败: client api: llm/listProviders failed: signal?.throwIfAborted is not a function
> 内置插件：暂时无法读取插件。
> 通用设置 → 权限：permission catalog has no active Host connection
> ```
> 右下角一直转「重新连接中…」。同一批 APK 在开发机（WebView 104）上完全正常。

## 一、不是四个毛病，是一个

四条报错看起来各不相干（Agent 预设 / 模型目录 / 插件清单 / 权限目录），实际上
是**同一条链断在最底下**：

1. 前端启动时 `dsh-client-connection` 用 `fetch` 拉连接描述符，拿到响应后第一句
   就是 `signal?.throwIfAborted();`（`client.browser.js`）；`dsh-api-gateway` 的
   `stream-client.js` 在开流、每次 `inbox.next()`、每片数据到达后也都调用它。
2. 这台机器的 WebView **没有** `AbortSignal.prototype.throwIfAborted`（Chrome 100
   才加）。`signal` 存在、方法不存在 ⇒ `TypeError`，**每一笔 RPC 都失败**。
3. 异常被 `ConnectionController.loop()` 吞掉（那是它设计上的容错：一次失败就
   重连），于是上层看不到任何错误，只有 `connection.generation` 恒为 `undefined`。
4. 各面板自己等不到数据，于是各报各的错 —— 权限面板把内部判定原样渲染成
   `permission catalog has no active Host connection`，模型面板把 provider 目录
   取空，插件面板只能显示「暂时无法读取插件」。

这解释了为什么「设置能打开、外观能改、字号能调」：那些是纯本地状态，不过
client API。凡是要过 RPC 的，一律挂。

## 二、为什么兼容层没兜住

`plugins/kxxy-host/web/compat.js`（`kxxy-webview-compat@12`）与 `modern.js`
（`kxxy-modern@2`）早就为这台机器的**上一代**问题做好了兜底 —— `AbortSignal.any`
（116）、`Promise.withResolvers`（119）、`Iterator`（122）、`Map.getOrInsertComputed`
（140 提案）、`dvh`、`:has()`、`@container` 全在补。但它们的目标基线是**WebView
104**（开发机实测值），而 `throwIfAborted` 是 **100** 才有的 —— 比基线更老，
从来没进过补齐清单。

一句话：**兼容层的下限（104）比这台设备的实际版本还高**。

同一代缺失的还有一批，只是还没轮到被点到：

| API | 首次可用 | 本仓库客户端里的用处 |
|---|---|---|
| `AbortSignal.prototype.throwIfAborted` | Chrome 100 | 每笔 RPC、每条流的取消检查 |
| `AbortSignal.reason` / `abort(reason)` | 98 | 取消原因（拿不到就 reject undefined） |
| `structuredClone` | 98 | 设置域的 `mutate(ops)`、pdf.js 的 `LoopbackPort` |
| `Array.prototype.findLast` | 97 | 时间线取「最后一条非空文本」 |
| `Object.hasOwn` | 93 | 散见各 `client.js` |
| `Array/String.prototype.at` | 92 | 同上 |
| `String.prototype.replaceAll` | 85 | 同上 |
| `AggregateError` | 85 | es-toolkit / pdf.js |
| `Intl.Segmenter` | 87 | 客户端主 chunk **模块顶层**就 `new` 了它 |

最后一条特别危险：它不在任何函数里，是模块求值时执行的 —— 真要缺，整个插件
入口连挂载机会都没有，症状会比现在更彻底。

## 三、修复：把补齐层的下界从 104 探到 85

改的全是 `plugins/kxxy-host/web/modern.js`（`kxxy-modern@2` → **`@3`**）：

1. **`AbortSignal.prototype.throwIfAborted`**：已取消则抛 `reason`；没有 reason
   就造 `AbortError`。**不能 `throw undefined`** —— 上游 catch 里普遍写着
   `error.message`，抛 undefined 会让它在第二个地方再炸一次，把真正的取消原因
   埋得更深。
2. **`AbortSignal.reason` / `abort(reason)`**：用一张 `WeakMap` 记住第一次的
   reason，并给 `AbortSignal.prototype` 装一个 getter。只在原生没有 `reason` 时
   安装（`!('reason' in prototype)`），新引擎一行都不动。不加这一段，`abort()`
   之后 `signal.reason` 恒为 `undefined`，`inbox.fail(signal.reason)` 会
   `reject(undefined)` —— 报错信息空白，分不清「用户取消」和「真的出错」。
3. **`structuredClone`**：按结构化数据语义实现（原始值 / 数组 / 普通对象 / Date /
   RegExp / Map / Set / ArrayBuffer / TypedArray / DataView + 环处理），函数与
   DOM 节点抛 `DataCloneError`，Blob 共享引用（真克隆要读字节，是异步的，而
   `structuredClone` 必须同步）。`{transfer}` 的分离语义无法在 JS 侧实现，忽略。
4. `findLast` / `findLastIndex`（Array 与 TypedArray）、`Object.hasOwn`、
   `Array/String.prototype.at`、`String.prototype.replaceAll`、`AggregateError`。
   `replaceAll` 走「转义成等价全局正则再交给原生 `replace`」而不是自己拼替换
   语义 —— `$&` / `$1` / 回调参数这些细节直接与规范一致。
5. **`Intl.Segmenter`** 的近似实现：按码位（含组合记号）切字素、按空白切词，
   不实现 `containing()`，也不合并 ZWJ emoji 序列。取舍写在代码里 —— 最坏结果
   是把一个 emoji 切成两半显示一个方框，比「整个插件入口求值失败」好得多。

全部走 `defIf`（`key in obj` 判断）：新引擎有原生实现时原样跳过，零语义改动；
补齐代码仍**完全自包含**，因为它要被 `Function.prototype.toString()` 取出来前置
到 blob worker / blob iframe 里（pdf.js 的渲染 worker 就跑在那儿）。

## 四、怎么验的（两条都能证伪）

**① `tools/test-modern.mjs` 新增 `[6]` 段（41 条断言）**：造一个「WebView 96」
的 vm realm —— 先把这批 API 全部删掉，并**先断言它们确实不存在**（否则后面的
绿全是假绿），再求值 `modern.js`，逐条验行为而不只是 `typeof`：取消后是否抛出
传入的 reason、`signal?.throwIfAborted()` 原句是否可执行、`structuredClone` 的
环引用与 TypedArray 同类型、`replaceAll` 的 `$&` 语义、二次求值幂等、以及
**前置进 blob worker 的那份源码在裸沙箱里也能补齐**。

> 踩到的坑：`vm.createContext({})` 的 realm 里**没有** `AbortController`
> （它不是语言内建）。第一版把宿主的类注进去再删原型方法，改到的是宿主自己的
> 原型 —— 断言之间互相污染。现在在 realm 内自建一份最小实现（`ABORT_SHIM`），
> 语义按 Chrome 96：有 `aborted`，`reason` 属性不存在。

**② `tools/verify-old-webview.mjs`（新增）真 Chromium 对照**：真浏览器里先把
这批 API 删掉，再按宿主的真实注入顺序（`compat.js` → `modern.js` → 页面脚本）
加载，跑 14 条与实际调用形态一一对应的断言，含**真起一个 blob worker** 验
`URL.createObjectURL` 那条注入链路；同时跑一组**不注入的对照组**：

```
装兼容层      OK 14/14
不装（对照组） ERR 抛出点本身存在=FAIL(false) | signal?.throwIfAborted()=THROW TypeError: …
```

对照组复现的正是用户截图里的那句 `signal?.throwIfAborted is not a function`。
没有对照组的断言不算验证 —— 它可能是永远绿的。

## 五、装完之后

- 首次启动会重解压运行时（`kxxy-modern@3` 与插件树指纹都变了），属预期。
- 设置 → 关于里新增一行 **系统 WebView**：直接读 `navigator.userAgent` 显示版本，
  低于 104 会标「偏低（已兼容）」。下次报障先看这一行。
- 想彻底摆脱这类问题，只能更新系统的 Android System WebView（应用无法自带
  WebView，也无法替用户升级）—— 但有了这一层，≤ 85 的差别都在兜底范围内。
