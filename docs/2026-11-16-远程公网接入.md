# 远程公网接入（落地版）

> 适用版本：连接器 `tools/remote-connector.mjs` v0.9.54 起。
> 这一版把「配对码」降级为引导凭证，长期凭证改成可撤销的设备会话；
> 公网入口必须带 `--public-origin`，否则只按局域网模式工作。

## 一、目标与边界

**目标**：手机不在同一个 Wi-Fi、不装额外 VPN，也能安全地用上电脑端 DSH。

**不是目标**：整个 Windows 桌面的屏幕投送与鼠标控制。那是另一套采集/编码方案。

**关键前提**：电脑要开机，DSH 与连接器都要在跑。没有任何一层能在电脑睡眠时替它响应。

## 二、三条路，选一条先跑通

| 方式 | 手机需要额外软件 | 地址形态 | 适合 |
|---|---|---|---|
| 同一个 Wi-Fi | 否 | `http://192.168.x.x:8080` | 家里/办公室日常，最快 |
| 私有组网（Tailscale 等） | 是，且要登录同一个账号 | 组网内网段 `100.x` | 只给自己用、不想暴露到公网 |
| 公网 HTTPS（隧道） | 否 | `https://<你的域名>` | 真正「在外面也能连」 |

**先跑通一条再叠第二条。** 三条同时配，出问题时无法判断是哪一层坏了。

## 三、公网方案 A：托管隧道（推荐先试）

以 Cloudflare 命名隧道为例（需要自己有一个域名，托管在 Cloudflare）：

```bash
# 1) 电脑上安装并登录（一次性）
cloudflared tunnel login

# 2) 建隧道，记下输出的 Tunnel ID
cloudflared tunnel create kxxy

# 3) 绑定域名（把 kxxy.example.com 换成你的）
cloudflared tunnel route dns kxxy kxxy.example.com

# 4) 配置文件 ~/.cloudflared/config.yml
#    ingress:
#      - hostname: kxxy.example.com
#        service: http://127.0.0.1:8080
#      - service: http_status:404

# 5) 先起连接器（注意 --public-origin）
node tools/remote-connector.mjs --public-origin https://kxxy.example.com

# 6) 另开一个终端跑隧道
cloudflared tunnel run kxxy
```

连接器带 `--public-origin` 之后会自动：

- 只监听 `127.0.0.1`（不再对局域网开放）；
- 只接受 `Host` 等于该域名的请求，其余一律 421；
- 会话 Cookie 标 `Secure`。

**不要反过来做**：把 `3080`（DSH 本身）暴露出去。它只认本机凭证、也没有配对门。

## 四、公网方案 B：自有服务器 + frp

适合已经有一台公网 VPS 的情况。多出的运维是证书与入口代理。

```ini
# 服务端 frps.toml
bindPort = 7000
vhostHTTPSPort = 443
```

```ini
# 电脑侧 frpc.toml
serverAddr = "<你的 VPS IP>"
serverPort = 7000

[[proxies]]
name = "kxxy"
type = "https"
customDomains = ["kxxy.example.com"]
localPort = 8080
```

证书建议交给 Caddy 或 Nginx 终结，然后反代到 `127.0.0.1:8080`，并**保留原始 Host**：

```nginx
server {
  listen 443 ssl http2;
  server_name kxxy.example.com;
  # ssl_certificate ...;

  location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header Upgrade $http_upgrade;      # 少了这行，流式对话必断
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 3600s;                    # 长连接，别用默认 60s
  }
}
```

`proxy_read_timeout` 与 `Upgrade` 两行是最容易漏、又最难从症状反推的两处：
漏了 Upgrade 的表现是「页面正常，一发消息就断」。

## 五、连上之后怎么验收

用脚本，不要用「页面能打开」当判据：

```bash
node tools/check-public-remote.mjs https://kxxy.example.com --code <当前配对码>
```

它会分五层给结论，并把不通的那层翻成下一步动作：

1. **DNS 解析** —— 域名有没有生效；
2. **TLS 证书** —— 是否签给这个域名、还有几天到期、是否自签；
3. **配对与来源校验** —— 401（码不对）/ 421（域名与 `--public-origin` 不一致）/ 429（被限流）；
4. **页面与鉴权** —— 上游 token 有没有换成会话；
5. **实时通道** —— WebSocket 能不能 101。

**脚本通过不等于远程可用。** 最后一步必须用手机做：

1. 关掉 Wi-Fi，只用蜂窝网络；
2. 扫一次连接串，进到 DSH 页面；
3. 发一条消息，确认是**流式**回复而不是一次性蹦出来；
4. 传一个小文件，再下载回来；
5. 让电脑休眠 30 秒再唤醒，确认 App 能恢复（或至少明确报错，不是白屏）。

## 六、安全上必须知道的三件事

**1. 配对码不是长期密码。**
它只用来换一张会话票据。会话存在连接器内存里，所以：

- 连接器重启 → 所有已配对设备失效，手机重连时会用连接串里的码自动换新票；
- 想立刻踢掉某台手机 → 重启连接器，或用管理接口：

```bash
# 看当前会话（只在本机可用，隧道进来的请求一律 404）
curl -H "x-kxxy-admin: <启动时打印的密钥>" http://127.0.0.1:8080/__kxxy_status

# 撤销全部
curl -X DELETE -H "x-kxxy-admin: <密钥>" http://127.0.0.1:8080/__kxxy_sessions
```

**2. 手机上的「移除」不等于撤销授权。**
那只是删手机里的记录。电脑侧的会话仍然有效 —— 界面里现在会明确这么写。
真要断开，用上面那条命令或重启连接器。

**3. 自签证书走「首次信任即固定」（TOFU）。**
手机第一次连自签 HTTPS 时会记下证书指纹，之后必须一致才放行。所以：

- 换了隧道证书 → 手机会拒绝连接并提示「证书和上次不一样」；
- 处理办法：删掉这台设备重新扫码（会重新固定一次）；
- 这是有意的取舍：配对一次就永久放行，等于把服务端身份校验永久关掉。

## 七、发布前必做（本次只改代码，没重建产物）

这一版改了 `plugins/kxxy-host/web/**`（界面）与两个 Kotlin 文件，两者都在
`runtime.zip` / APK 里。**代码改了不等于设备会变**：

1. 补丁集标记已从 `@24` 升到 `@25`，四个位置必须一起改（已改好）：
   `tools/build-runtime.mjs`、`tools/upgrade-dsh-runtime.mjs`、
   `engine/RuntimeInstaller.kt`、`tools/fixtures/DshRuntimeUpgradeTest.kt`。
2. 重建运行时，再打包 APK：

```bash
node tools/build-runtime.mjs --stage .cache/stage --asar .cache/app.asar \
  --plugins plugins --out dist/runtime.zip --manifest dist/manifest.json

powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-apk.ps1 -Offline -Gradle <gradle.bat>
```

3. 重建前跑 `node tools/verify-runtime.mjs` 会报
   `标记文件不含 kxxy-patchset@25` —— 那是**产物过期**的自检结果，不是代码错。
   重建后重跑应为通过。

  只能靠上面第五节手工验收。

## 九、常见症状对照

| 现象 | 大概率是 | 先查什么 |
|---|---|---|
| 手机上 421 | 域名与 `--public-origin` 不一致 | 两边逐字符对比，含 `https://` 与端口 |
| 配对一直 401 | 码过期（`--code-ttl`）或用了旧码 | 看电脑终端**当前**打印的那行 |
| 配对成功但白屏 | 隧道没转发 WebSocket | 验收脚本第 5 层 + 反代 `Upgrade` 头 |
| 页面能开，一发消息就断 | 同上，或会话在 upgrade 被丢 | 检查隧道是否原样转发 `Cookie` |
| 一直显示「上次连接失败」 | 电脑侧 DSH 没开 / token 过期 | 电脑上直接开 `127.0.0.1:3080` |
| 每次都要重新扫码 | 连接器被反复重启 | 会话在内存里，这是设计而非故障 |
