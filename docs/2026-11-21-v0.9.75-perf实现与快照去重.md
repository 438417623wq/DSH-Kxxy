# v0.9.75 —— perf 从「做不到」改成「做成了」，--link-dest 真去重

> 起因：用户第三次贴出同三条问题（硬链接、perf 缺失、sklearn/cv2 缺失）。
> 其中 **perf 这一条我上一版判错了** —— 结论是「应用域拿不到 perf_event_open」，
> 但那个结论来自 simpleperf 的报错，不是内核的真实答复。这一版重新取证后，
> perf 变成了一个能用的命令。

## 1. 三条问题的最终定性

### 1.1 硬链接：不可能，但「去重」这个目的现在可以达成

`ctypes` 直接调 libc，在应用域逐项试（Redmi K60 Pro / f2fs）：

| 操作 | 路径 | 结果 |
| --- | --- | --- |
| `link(2)` | `files/home` | rc=-1 **errno=13 EACCES** |
| `linkat(2)` | `files/` / `cache/` | rc=-1 **errno=13 EACCES** |
| `FICLONE`（reflink） | `files/home`（f2fs） | **errno=13 EACCES** |
| `rename(2)` 同目录 | `files/` | 成功（dev 65060） |
| `symlink(2)` 同进程 | `files/` | 成功 |
| `link(2)` | `/data/local/tmp`（`u:r:shell:s0`） | **EACCES** |

三个否定结论：

- 不是 `protected_hardlinks`（那是 EPERM），是 `EACCES`；
- 不是文件系统只读或配额（同目录 `rename` 成功）；
- 不是应用权限不够（连 `u:r:shell:s0` 的 adb 域也被拒）。

即 sepolicy 摘掉了 `file link`，改它要 root。**reflink 这条路也断了** ——
f2fs 没有 reflink，且 SELinux 对未知 ioctl 同样回 EACCES，所以「同数据块、
不同 inode」这个替代品也不存在。用户态能做到的共享数据的原语只有软链。

于是把「去重」这个真实目的用软链实现（见 §2），`ln` 与 `kxxy-rsync` 的退化
契约保持说清原因不变。

### 1.2 perf：上一版判错，这一版做成

上一版的证据是 simpleperf 的两句报错：

```
simpleperf E workload.cpp:36] Running child command in app uid isn't allowed.
simpleperf E environment.cpp:340] Failed to SetProperty debug.perf_event_max_sample_rate to 100000
```

据此写了「应用域拿不到 `perf_event_open`」。**这是把封装层的拒绝当成了内核的拒绝。**
直接 `syscall(241)` 取证（aarch64）：

```
attr: u:r:runas_app:s0:c142,c257,c512,c768
paranoid: -1
SW task-clock / self      fd=4  errno=0
HW cpu-cycles / self      fd=4  errno=0
SW cpu-clock / self       fd=4  errno=0
```

`perf_event_paranoid=-1`（最宽松）+ 内核放行。simpleperf 的两条限制都是它自己的：
`-- cmd` 模式拒绝在 app uid 起子进程；`record` 启动时无条件 `SetProperty`，
应用域改不了系统属性 —— 即使先 `adb shell setprop` 把值设成 100000，它照样失败
（失败的是「设」这个动作本身）。

所以这一版**自己实现 perf**（`libexec/kxxy-tools/perf.py`，零第三方依赖），
`perf stat` / `perf record` / `perf report` / `perf list` 四个子命令。

### 1.3 sklearn / cv2：原生不可能，但失败信息现在能指路

`sklearn` 与 `opencv-python` 官方没有 Android 构建，PyPI 只有 manylinux（glibc）
轮子；bionic 的 CPython 连 `ld-linux` 都起不来，交叉编要 cythonize 40+ 扩展。
`kxxy-py`（glibc 容器里的 python）本来就能用 —— 上一版已验收 sklearn 1.9.1 /
cv2 5.1.0。缺的是**发现路径**：原生 `python -c "import sklearn"` 只回一句
`ModuleNotFoundError`，用户不知道有 `kxxy-py`。这一版在 site-packages 挂了个
`.pth` 钩子，把错误信息换成可执行的下一步（见 §3）。

## 2. `--link-dest` 的真去重（`KXXY_RSYNC_LINK_MODE=symlink`）

rsync 的 `--link-dest` 在本机会静默退化成整份复制（rc=0、inode 不同、空间照占），
这是最坏的失败方式：备份脚本以为自己在做增量，实际每天写一份全量。

新实现是「两次作业」，产物是**完整快照**且未变更文件不占空间：

1. `rsync --compare-dest=<base>` —— 只复制与基准不同的文件；
2. linkify —— 基准里有、目标里没有的文件，建**绝对路径符号链接**指回基准。

真机（`rsync 3.5.2`）：

```
$ kxxy-rsync -a --link-dest=../base src/ s2/      (KXXY_RSYNC_LINK_MODE=symlink)
kxxy-rsync: 本机 SELinux 拒绝 link(2)，改用 --compare-dest + 符号链接
            基准 …/snaptest/base
kxxy-rsync: 已链接 2 个未变更文件到基准（目标里已有 1 个，跳过）
rc=0

s2/a.txt      -> …/base/a.txt          （未变更 → 软链）
s2/b.txt      -rw-rw-rw- 16 B          （变更 → 真文件）
s2/d.txt      -rw-rw-rw- 10 B          （新增 → 真文件）
s2/sub/c.txt  -> …/base/sub/c.txt
cmp s2/a.txt base/a.txt → 一致；cmp s2/b.txt src/b.txt → 一致
du -sk base s2 → 19 / 15（数据没有第二份）
```

**安全边界**：rsync 写入走「临时文件 + rename」，不会顺着软链改写基准；
但 `--inplace` 会 —— 所以带 `--inplace` 时直接拒绝（rc=1），不给出会毁快照的组合。

## 3. perf 的实现要点（踩过的三个坑）

1. **短命令必挂**：`perf stat -- true` 这种 1 毫秒就退出的命令，`Popen` 返回后
   再 `perf_event_open(pid=child)` 必然 `ESRCH`。改成 `fork()` → 子进程自己
   `SIGSTOP` → 父进程 `waitpid(WUNTRACED)` 确认已停 → 开事件 → `SIGCONT`。
   效果：`/system/bin/true` 也能拿到 18,332,838 cycles / 16,607,971 instructions。
2. **环形缓冲 mmap 报 EINVAL**：内核 `perf_mmap()` 里有一句
   `if (event->cpu == -1 && event->attr.inherit) return -EINVAL;`（全局继承的
   per-task 事件共用一个环会串数据）。所以 `record` **不能**带 `inherit` 位 ——
   代价是只采样目标进程本身，不含它的子进程。
3. **符号化**：解析 ELF 的 `PT_LOAD` 把采样地址换算成文件偏移，再查
   `.symtab`/`.dynsym`（`st_value` 同样是 vaddr，用同一套换算），
   C++ 名走引擎里已有的 `c++filt`。V8 的 JIT 代码落在匿名可执行映射里，
   照实显示 `[anon-exec]`，不假装能解。

真机效果：

```
$ perf stat -- node -e '…'
      147.870413  msec  task-clock
     378,566,678  cycles
     582,567,480  instructions
       2,299,289  branch-misses
  1.54  insn per cycle     3.94  GHz  effective（指令吞吐）

$ perf record -F 999 -g -- node hot.js && perf report
    1723    88.68%  MainThread  anon                    ← V8 JIT
      61     3.14%  MainThread  v8::SandboxHardwareSupport::InitializeBefor...
      43     2.21%  MainThread  [vdso]

$ perf record -F 500 -p <python pid> --duration 1.5 && perf report
     202    27.08%  python      [vdso]
     138    18.50%  python      _PyEval_EvalFrameDefault   ← 浮点循环，符合预期
      77    10.32%  python      PyDict_New
      71     9.52%  python      PyFloat_FromDouble
```

`lib/python3.14/site-packages/kxxy_hint.pth` → `import _kxxy_hint`，挂一个
**追加在 `sys.meta_path` 末尾**的 finder。只在 `sklearn / cv2 / opencv / joblib /
threadpoolctl` 真正导不到时改错误信息：

```
ImportError: scikit-learn 只有 glibc 的 manylinux 轮子，bionic 的原生 Python 装不了（不是没装，是装不上）。
  直接用：      kxxy-py -c 'import sklearn'
  装更多包：    kxxy-glibc -c 'pip install scikit-learn'
```

## 6. 用法

```sh
perf list                          # 支持的计数器（现场试开，✓/✗）
perf stat -- <命令>                # 计数器汇总（含 IPC / 分支失败率）
perf stat -p <pid> 3               # 对已有进程采 3 秒
perf record -F 999 -g -o p.data -- <命令>
perf record -p <pid> --duration 5 -o p.data
perf report -i p.data              # 按符号汇总；--stack 看调用链

KXXY_RSYNC_LINK_MODE=symlink kxxy-rsync -a --link-dest=../base src/ snap2/
KXXY_RSYNC_LINK_STRICT=1 kxxy-rsync …   # 只要硬链接语义，建不出就失败
```

## 7. 已知限制

1. 硬链接的 `st_ino` 相同，在这台 ROM 上永远做不到（`link(2)`/`linkat(2)`/
   `FICLONE` 全 EACCES）。`rsync --link-dest` 的 symlink 模式解决了「空间去重」，
   但语义不是硬链接：**直接对快照里的软链写入会改到基准**（rsync 自身不会）。
2. `perf record` 不跟随子进程（`inherit` 与 mmap 互斥），也不解 frame pointer 之外的栈。
3. `perf` 依赖引擎自带的 python（`bin/python`），首次调用约 80 ms 启动开销。
4. 内核态采样默认关闭，`perf stat` 会在被拒时自动退到「只统计用户态」并注明。
