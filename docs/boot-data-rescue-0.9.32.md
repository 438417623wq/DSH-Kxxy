# 0.9.32：会话权限与凭据写入锁救援

## 本轮问题

0.9.31 日志显示基础凭据和工作区记录已可访问，但仍存在：

- `sessions/<workspace>/session-<uuid>` 的目录读取被拒绝（EACCES），工作区服务启动失败。
- `.credentials.yaml.lock` 写入锁等待超时，connection 必需服务启动失败。

因此控制台显示 `AUTH UNAVAILABLE / connection.no-service` 是基础服务未启动的结果，不应关闭鉴权或先重建所有插件依赖。

## 覆盖安装后操作

1. 覆盖安装 `Kxxy-0.9.32.apk`，不卸载、不清数据。
2. 启动页进入 **诊断/救援 → 修复会话权限和凭据锁**。
3. 已知曾使用 Root 的，可选择 **用 Root 修复会话和失效锁**，再确认本次授权，并在 Root 管理器中允许。
4. 救援先核验旧引擎退出，按日志检查目标；会话内容、凭据和插件清单不会被清空。
5. 修复后重新启动；如果仍失败，保存新诊断日志。活跃锁、未知锁格式、无法确认退出的进程或公开存储软链会明确报告，不会强行处理。

## 安全边界

- 只修近期明确报错的私有 session 范围及必要祖先，限制遍历规模与时间，不扫描全部 home、不跟随符号链接。
- 锁协议来自当前打包 `@deepseek-ai/dsh-atomic-write`：锁记录是 PID 加换行，只有信号 0 返回 ESRCH 才能证明持锁者退出。
- 读不到锁、EPERM、活 PID、未知记录或已存在的接管 claim 都不能凭文件年龄/超时删除。
- 仅确认失效后原子隔离锁并保留备份；不读取或改写凭据内容，不根据锁里的 PID 盲目杀进程。
- Root 授权仅用于本次必要的元数据恢复和检查，不改变后续普通模式，不放开控制台鉴权。

## 验证说明

本地编译与生产 Kotlin/JVM、锁协议行为测试不代替 Android 真机 Root/SELinux/进程验证。最终以手机覆盖安装后的真实启动与新日志为准。构建和回归结果见 `dist/Kxxy-0.9.32-verification.json`。
