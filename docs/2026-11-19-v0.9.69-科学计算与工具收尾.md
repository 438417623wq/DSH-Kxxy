## 1. 硬链接：两层原因，只有一层能修

`link(2)` 在 `/data`（f2fs，`getenforce` = Enforcing）上返回 `EACCES`，这是 SELinux 的策略边界，**不绕过**（`sepolicy` 改不动，也不该改）。能做的是「别让脚本因为一条 `ln` 整体挂掉」。

但上一版做完降级后真机仍然失败，原因不在策略，而在包装器自己：

```
$ $PREFIX/bin/ln a b
Try '/data/user/0/app.kxxy/files/engine/bin/coreutils --help' for more information.
rc=1
```

Termux 的 coreutils 是「单二进制 + 按 `argv[0]` 分发」，显式入口是 `--coreutils-prog=PROG`。`coreutils ln a b` 会把 `ln` 当非法参数，回一句帮助提示、**stderr 里没有 Permission denied** —— 于是包装器判定「这不是可退化的错误」，把帮助提示原样吐出来，退化逻辑等于没生效。

正确形式在真机上的输出：

```
$ $PREFIX/bin/coreutils --coreutils-prog=ln za zb
coreutils: failed to create hard link 'zb' => 'za': Permission denied
```

现在 `bin/ln` 的行为矩阵（`KXXY_LN_STRICT=1` 时一律严格）：

| 调用 | 结果 |
| --- | --- |
| `ln a b`（SELinux 拒绝） | `cp -a a b`，rc=0，stderr 提示已退化为独立副本 |
| `ln a b` + `KXXY_LN_STRICT=1` | 原样报错，rc=1 |
| `ln -s a b` | 透传 `--coreutils-prog=ln -s`（软链不受这条策略限制） |
| `ln nosuch b` | 不降级，报错退出（否则「找不到文件」会被伪装成一次成功复制） |
| `ln e1 e2 dir/` | 逐个 `cp -a` 进目录 |

`rsync --link-dest` 仍会退化为 copy（它自己调 `link(2)`，不走我们的 `bin/ln`），这是策略决定的，本版不改；`--link-dest` 的价值是省空间，退化后只损失空间、不损失正确性。

## 2. pandas 回归的真正原因：锚点看不见「新增文件」

`pandas` 在 17:40 还正常、升级后消失，不是被删了，而是**从来没解出来**：

- `RuntimeInstaller.isComplete()` 的十六条锚点全部只判「既有文件还在不在」；
- 旧 `runtime.zip` 里没有 pandas，锚点照样全过 → `isComplete()` 判真 → 直接跳过解压。

所以这类「只加文件」的运行时变更**只能靠 `PATCHSET_MARKER` 让老设备重解一次**。本版把它推到 `@28`（27 是上一轮 stage 重解，28 是这一轮的 pydeps + `bin/ln` 内容变更）。

同时补两道构建期防线，避免再把陈旧 stage 当成品：

1. `tools/lib/stage-fresh.mjs` —— `build-runtime` 开跑前比对 stage 与 deb 清单，陈旧就失败并提示 `prepare-stage`；
2. `build-runtime` 里点名断言 `site-packages/{numpy,pandas,scipy,matplotlib,lxml,PIL}/__init__.py` 必须在，缺一个直接构建失败。

## 3. 纯 Python 依赖内置化（`tools/lib/pydeps.mjs`）

pandas 与 matplotlib 的 deb 里 `Depends` 只有 numpy/openblas 这类原生件，`dateutil`/`packaging` 交给了 `pip`；而 Termux 主仓索引里 `python-dateutil`、`python-packaging`、`python-pytz`、`python-six`、`python-pyparsing`、`python-fonttools` **零命中**。于是「离线可用」这条前提在 pandas 上是假的。

处置：直接内置纯 Python wheel（全部 `*-none-any.whl`，无 ABI 概念）：

| 包 | 版本 | 为谁服务 |
| --- | --- | --- |
| python-dateutil | 2.9.0.post0 | pandas（刻意停在 2.9，4.0 是新大版本，pandas 3.1.1 仍按 2.x API 使用） |
| six | 1.17.0 | dateutil |
| tzdata | 2026.6 | pandas 时区（Android 无系统 tzdata） |
| pytz | 2026.6 | 兼容老代码 |
| packaging | 26.3 | matplotlib |
| cycler | 0.12.1 | matplotlib |
| pyparsing | 3.3.3 | matplotlib |
| fonttools | 4.68.0 | matplotlib 字体 |
| sympy | 1.14.0 | 符号计算（Termux 无包） |
| mpmath | 1.4.1 | sympy |

实现要点：

- 只用**钉版端点** `https://pypi.org/pypi/<name>/<version>/json`。不用「最新版」端点 —— 那个版本号会漂移，上游一发新版构建就随机构建失败；
- 每个 wheel 下载后校验 sha256，实际解析结果写进 `tools/pydeps.lock.json`（提交进仓库），下次构建直接用锁文件，不再联网取元数据；
- `*.data/` 目录整段跳过（那是 wheel 里属于前缀的 man/头文件，不是 import 需要的）；
- 构建期断言这 10 个包的 `__init__.py` 都在最终条目里，少一个就失败；
- `tools/fetch-pydeps.mjs` 额外把解包结果落到 `.cache/pydeps-site/`，用于单点推真机验证（本轮就是这么验的）。

## 5. 一个自己挖的坑：`bin/pnpm` 换成原生二进制后锚点判假

把 `bin/pnpm` 从 corepack shim 换成 Termux 的 pnpm 本体（ELF）后，装完 0.9.69 的第一次启动**整个 runtime 安装失败**：

```
W KxxyRuntime: runtime probe: packaging wrapper is not a sh shim: bin/pnpm (␡ELF…)
E KxxyRuntime: java.lang.IllegalStateException: APK runtime verification failed; offline repair can be retried
E KxxySupervisor: 同一条启动错误连续出现 2 次，重试已无意义
```

原因：`isComplete()` 的锚点 15（缺陷 CT 加的那条）要求 `PACKAGING_WRAPPERS` 里的
`bin/{corepack,npm,npx,pnpm,zipalign,bundletool}` 都是 `#!/system/bin/sh` 包装器
（或 corepack 的 dist 软链）。`bin/pnpm` 现在是 ELF，两种合法形态都不是 → 判假。

连带效应比「安装失败」本身更隐蔽：

- 安装失败 ⇒ `.relink` 标记**不会写**（它写在 `writeStamp()` 之后）⇒ 插件启动时
  `relinkAll()` 直接返回 0 ⇒ 所有已装扩展的 `bin/` 视图（`bin/ruby`、`bin/irb`、
  `bin/php`…）全部消失；
- 安装失败 ⇒ 插件进程根本没起来 ⇒ `staleExtensions()` 也不会跑 ⇒ 池内容变了
  （node-tools 从 16.3 MB 变 22.5 MB、多了 webpack）也不会重装。

于是「webpack / irb / ruby 仍缺」在很大程度上不是包的问题，而是**安装被判失败**。
而手工跑 `touch extensions/.relink` 再 `relinkAll()` 立刻回来了 30 个扩展 —— 正好反证。

处置：锚点 15 增加第三种合法形态 —— `bin/pnpm` 允许是 ELF（魔数 + 40 MiB 体积下限，
防「截断的半截文件」蒙混），其余四个仍是 sh 包装器。

## 7. 已知边界

- `link(2)` 的 SELinux 边界保持不动，硬链接在 `/data` 上永远不可用；跨分区（如 `/data/local/tmp` → `/data`）同样不行。
- `sklearn`、`cv2`：Termux 无包，PyPI 只有 manylinux wheel（bionic 不兼容），源码编译要 Cython + OpenMP 全链，本版不做。
- `torch` 走扩展池（`python-torch` 2.15.0，池 103 MiB / 解包 375 MiB），按需安装，不预装。
- `fortran` 池解包 1.31 GiB（flang 带 mlir/libllvm 一整套），安装前需确认设备空间。
