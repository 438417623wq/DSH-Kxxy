## 1. 硬链接：不是"没做好"，是内核不让做

### 1.1 取证（这次把每一层都单独排掉了）

用 `ctypes` 直接打 libc，绕开 coreutils 的一切包装：

| 检查项 | 实测 | 说明 |
|---|---|---|
| 调用者 uid | 10398 | 与文件 owner 相同 |
| 源文件 owner / mode | 10398 / `0666` | 可读可写 |
| 父目录 owner | 10398 | 可写 |
| `stat.dev`（源与目标） | 65060（同一设备） | 不是跨文件系统 |
| `link(2)` 同目录 | **EACCES (13)** | |
| `link(2)` 跨目录 | **EACCES (13)** | |
| `linkat(2)`，`AT_FDCWD` | **EACCES (13)** | |
| `symlink(2)` | **OK** | 同一个进程、同一个目录 |
| `open(O_CREAT)` | **OK** | |
| 进程 SELinux 域 | `u:r:untrusted_app_27:s0:c142,…` | `ps -Z` |

DAC 全通过、同设备、同 uid 仍是 `EACCES`，只有一种解释：**LSM 拒绝 `file link`**。
排除项：`fs.protected_hardlinks` 只会回 `EPERM`；跨挂载点会回 `EXDEV`；目录会回 `EPERM`。

结论：这台 ROM 的 sepolicy 把 `link` 从 `untrusted_app` 域的 `app_data_file`
权限里摘掉了（Android 11 起有专门收紧，防硬链接绕过 per-app MLC 隔离）。
**改 sepolicy 要 root，APK 做不到。这条边界与 `KXXY_LN_STRICT` 无关，开不开都不可能成功。**

### 1.2 所以改了"退化的方向"

旧行为：失败 → `cp -a` 落一份**独立副本**，rc=0。
问题：`cp -a` 是两份数据，之后互不同步 —— 这正是你看到的「inode 不同 + 去重失效」，
而且比"报错"更容易埋雷（脚本以为建好了链接，实际拿了两个会分叉的文件）。

新行为（`tools/build-runtime.mjs` 的 `hardlinkWrappers`）：

| 环境变量 | 行为 |
|---|---|
| 默认 | **建符号链接**（绝对路径）。同一份数据、不额外占空间、改一处两处都变 |
| `KXXY_LN_STRATEGY=copy` | 退回独立副本（需要能独立修改副本时） |
| `KXXY_LN_STRICT=1` | 直接失败，并在 stderr 说明原因与两个替代开关 |
| `KXXY_LN_QUIET=1` | 关掉那一行说明 |

符号链接必须用绝对路径：`ln ../x dir/y` 这种相对源若原样建软链，落点一变就悬空。

真机验收（本地用「必报 EACCES 的假 coreutils」驱动，逻辑一致）：

```
ln a.txt link1        →  lrwxrwxrwx link1 -> /abs/path/a.txt          rc=0
ln a.txt b.txt dir    →  dir/a.txt, dir/b.txt 均为软链                rc=0
KXXY_LN_STRICT=1 ln   →  报 EACCES + 两行替代说明                      rc=1
```

**仍然做不到的**：`st_ino` 相同。`rsync --link-dest`、`cp -l`、`git worktree` 共享对象
都走同一条 `link(2)`，因此**全部不可用**，这是平台能力缺失，不是配置问题。需要去重的场景
改用「单副本 + 符号链接视图」，或 `KXXY_LN_STRATEGY=copy` 明确接受空间代价。

## 2. Fortran：`--version` 一直是假象

### 2.1 真实状态

v0.9.71 只验了 `flang --version` 就记为「可用」。这次真编译：

```
flang -O2 -o out1 t.f90
ld.lld: error: cannot open crtbegin_dynamic.o: No such file or directory
ld.lld: error: cannot open …/lib/clang/21/lib/aarch64-unknown-linux-android24/
                libclang_rt.builtins.a: No such file or directory
ld.lld: error: unable to find library -l:libunwind.a
```

即：**前端在，链接工具链整个缺**。根因是池构建**不解析 `Depends`**，而
`flang` 的依赖链是 `clang → libcompiler-rt → ndk-sysroot / lld / llvm / mlir`。

### 2.2 修法：不补 200 MB 依赖，只补三个路径

三件东西引擎里本来就有：

- `<root>/lib/crtbegin_dynamic.o`、`crtbegin_so.o`、`crtend_android.o`、`crtend_so.o`
- `<root>/lib/libunwind.a`
- `<root>/lib/clang/21/lib/linux/libclang_rt.builtins-aarch64-android.a`

flang 按**自身位置**推资源目录（`<extend>/lib/clang/<ver>`）和默认库目录（`<extend>/lib`），
所以只要在池里建软链即可。新增 `ensureFortranToolchain()`（`extinstall.mjs`），
装完 / 每次自愈都跑一次：

1. `crt*.o` + `libunwind.a` → `<extend>/lib/`
2. builtins → `<extend>/lib/clang/<ver>/lib/aarch64-unknown-linux-android{21..36}/libclang_rt.builtins.a`

建 21–36 全部 triple 是因为 minSdk 由 flang 二进制编译期决定（实测 `android24`），
每条只是一个软链，换池/换 SDK 后不用再猜。

### 2.3 真机验收

```
flang -O2 -o out1 t.f90 && ./out1        →  ok=42
flang -J mods -c m.f90                   →  mods/m.mod 生成
flang -I mods -o t2 t2.f90 m.o && ./t2   →  dbl=42
```

`-J`（gfortran 的模块目录开关）flang 原生就认，不需要参数改写。

### 2.4 `gfortran` 这个名字

新增 `bin/gfortran`（`fortranWrappers()`）：`exec <root>/bin/flang "$@"`。
池未装时报 127 并提示去控制台装 fortran 池。

实测 flang 21.1.8 对 gfortran 常用命令行**全部接受、无需改写**：
`-c -o -O2 -g -fPIC -shared -I -L -l -J -cpp -std=f2018 -ffree-form -ffixed-form -fopenmp`。
这样 `./configure`、Makefile、CMake 工具链文件里硬写 `gfortran` 的项目能直接跑。

它仍然是**前端**：`-fdec`、部分 `-std=legacy` 行为、`-fcheck=all` 的细节到不了位，报错文案也不同。

## 3. glibc 边界：proot 打通了（含完整配方）

### 3.1 之前为什么失败

`link(2)` 被禁这条同样卡死了所有"用垫片跑 glibc 轮子"的路，此前四轮补库
（libavcodec → glibc soname → `ld-linux-aarch64.so.1` → 软链到 `/system/bin/linker64`）
最后停在 `is not accessible for the namespace "(default)"`。

### 3.2 关键发现：`PROOT_LOADER`

Termux 的 proot **不是自带内嵌 loader**，而是从
`$PREFIX/libexec/proot/loader` 读。只解 `bin/`、`lib/` 就会漏掉它，
症状是**任何** `execve` 都回 ENOENT —— 连 `proot -r / /system/bin/sh` 都跑不起来，
看着像"proot 在这个 ROM 上不可用"。补上 loader 并指路即可：

```sh
PROOT_LOADER=<...>/libexec/proot/loader
PROOT_LOADER_32=<...>/libexec/proot/loader32
```

第二个关键点：`--link2symlink`。dpkg 建 `status-old` 用的是 `link(2)`，
不加这个开关就是 `error creating new backup file '/var/lib/dpkg/status-old': Permission denied`。

### 3.3 可复现的最小配方（真机已验证）

```sh
R=<engine>; P=<proot 安装目录>
env LD_LIBRARY_PATH=$R/lib:$P/lib TMPDIR=$TMP \
    PROOT_TMP_DIR=$TMP \
    PROOT_LOADER=$P/libexec/loader \
    PROOT_LOADER_32=$P/libexec/loader32 \
  $P/bin/proot -r $P/rootfs -0 --link2symlink \
    -b /dev -b /proc -b /sys -w / \
    /usr/bin/env -i PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin \
      HOME=/root <命令>
```

注意两点：
- **必须 `env -i` 重置 PATH**：proot 默认继承 Android 的
  `/product/bin:/apex/...:/system/bin`，在 rootfs 里全不存在，`ls`/`head` 都找不到。
- `-b /etc/resolv.conf` 在 Android 上不存在（`proot warning: can't sanitize binding`），
  但 DNS 仍可用（走 netd），所以不必绑。

### 3.4 真机结果

rootfs：ubuntu-base 24.04 arm64（29.8 MB 压缩）。解压要用
`tar --hard-dereference`，否则 `ld-linux-aarch64.so.1` 这类**硬链接条目会被跳过**，
后面 `execve` 全 ENOENT（我第一次就踩了）。

```
apt-get update                       → Fetched 38.0 MB in 14s (2732 kB/s)
apt-get install python3-pip          → apt_rc=0, Python 3.12.3
pip install --ignore-installed \
    numpy scikit-learn opencv-python-headless → pip_rc=0

numpy 2.5.5
sklearn 1.9.1
cv2 5.1.0
LinearRegression: coef=2.0 intercept=0.0     ← 真拟合，不是只 import
cv2: shape (8,8,3) mean 20.0                ← 真数组运算
```

`pip` 装 numpy 时要用 `--ignore-installed`：apt 装的 numpy 1.26.4 没有 RECORD，
否则 `Cannot uninstall numpy 1.26.4, RECORD file not found`。

### 3.5 这条路的代价

- 体积：proot 260 KB + loader 24 KB + 两库 48 KB + rootfs 29.8 MB（解压约 80 MB）。
- 性能：ptrace 拦截，IO 与进程创建明显变慢（安装/编译会久，纯计算影响较小）。
- `joblib` 仍然警告串行 —— 因为 **Android 没有 `/dev/shm`**，`_multiprocessing.SemLock`
  失败，这是宿主限制，proot 里也一样。

## 4. 仍然不可用的

| 项 | 状态 | 原因 |
|---|---|---|
| `julia` / `dotnet` / `wkhtmltopdf` | 未发 | 官方只发 glibc 构建；可在 proot rootfs 里 `apt install`，但需联网，未预装 |
| `perf` | 未发 | 除 glibc 外还要内核 `perf_event_open` 权限，app 域拿不到 |
| `sklearn` / `cv2` 在**原生**引擎 Python 里 | 仍缺 | bionic ABI 不兼容，NDK 交叉编译未做；已由 proot 提供等价能力 |
| 真硬链接 | 不可能 | 见第 1 节 |
