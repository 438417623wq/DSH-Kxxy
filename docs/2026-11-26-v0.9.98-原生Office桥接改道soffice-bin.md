# v0.9.98：原生 Office 后端真正生效（soffice.bin）+ 预置收尾

> 起因：v0.9.97 装到真机后，`office_engine.backend` 仍然是 `wasm`。查下去发现桥接
> 本身写对了，但它调的那个可执行文件在 proot 里跑不起来。顺带修掉两处预置脚本的
> 小毛病（重装扩展后离线包白占 580 MiB、`all` 只看最后一条的退出码）。

## 1. `/usr/bin/soffice` 在 proot 里必失败

`/usr/bin/soffice` 不是 LibreOffice 本体，而是 **oosplash 启动器**：它启动时先自检
`/proc`，而容器里那份自检通不过 —— 于是连 `--version` 都不回，直接退 1：

```
$ kxxy-glibc -c 'soffice --version'
ERROR: /proc not mounted - LibreOffice is unlikely to work well if at all
rc=1
```

同一个容器里，它包装的真身 `program/soffice.bin` 一切正常：

```
$ kxxy-glibc -c '/usr/lib/libreoffice/program/soffice.bin --version'
LibreOffice 24.2.7.2 420(Build:2)                      rc=0

$ kxxy-glibc -c '...soffice.bin --headless --convert-to pdf --outdir /tmp/o /tmp/a.fodt'
convert /tmp/a.fodt as a Writer document → /tmp/o/a.pdf
                                                      rc=0（8 599 字节 PDF）
```

所以 v0.9.97 的桥接虽然「探测到文件存在就报 native」，真正转换那步必然失败，又按
设计回退 WASM —— 用户看到的仍是 `backend: "wasm"`。

### 修法
`patchLibreOfficeKitGlibcNative` 改成调 `program/soffice.bin`，同时修掉两个连带问题：

| 问题 | 原状 | 现在 |
|---|---|---|
| 探测路径 | `rootfs/usr/bin/soffice` | `rootfs/usr/lib/libreoffice/program/soffice.bin` |
| 根目录回退 | `../../../../..` 少一级，退到 `lib/` | `../../../../..`（`lib/index.js` → 引擎根）正确 |
| 转换结果 | 只看退出码 | **产物必须存在且非空** |

最后一条不是洁癖：`soffice.bin` 对不认识的输入（例如没有 `infilter` 的 `.txt`
`--convert-to txt`）会以 **0** 退出却什么都不产出。只看退出码就等于「空转换算成功」，
上层会写出一个 0 字节文件，比报错更难查。

```js
let bytes;
try { bytes = await readFile(expected); } catch {
  throw new Error(`glibc soffice produced no output (${format}): ${stderr.trim()}`);
}
if (bytes.length === 0) throw new Error(`glibc soffice produced an empty ${format}`);
```

失败仍然无缝回退 WASM（实时预览本来就由 WASM 渲染器出图，`nativePreview` 保持
`false`），`KXXY_OFFICE_BACKEND=wasm` 可强制走 WASM。

### 补丁集为什么又涨了一格（@43 → @44）
v0.9.97 已经把 `lib/index.js` 换过一次。设备侧 `isComplete()` 的锚点 11 只看
`kxxy-host/patchset.version` 这一行；标记不变时它判「运行时完整」，**连 `lib/` 都不
重解压**。文件路径没变、锚点全过 ⇒ 只改内容而不涨编号，已装 0.9.97 的设备会安静地
继续跑旧桥接 —— 正是这次要修的那个版本。

## 2. 第二个坑：`cli.js` 自带一份实现，只改 `index.js` 等于没改探针

`libreoffice-kit` 发布的是一个**打包过的** `lib/cli.js`（≈98 KB），它把
`discoverRuntime()` 与 `execute()` 整段内联进去了 —— 和 `lib/index.js` **逐字节相同**：

```
$ grep -n "async function discoverRuntime" lib/index.js lib/cli.js
lib/index.js:1864:async function discoverRuntime(options) {
lib/cli.js:1866:async function discoverRuntime(options) {
```

`capabilities --json`、`convert`、`render` 三条命令走的都是 cli.js 自己那份。所以只给
`index.js` 打补丁时：**库路径（引擎内部转换）已经是 native，而能力探针永远报 `wasm`**
—— 恰好是用户复现时看的那一个指标，于是「修好了也像没修」。

补丁改成两个入口各注一遍（`applyGlibcNativeTo()` 复用同一套锚点），并且
`tools/test-office-glibc-native.mjs` 把「两个文件都在补丁目标里」钉成断言。

## 3. 第三个坑：`-env:UserInstallation` 在容器里必退 81

桥接原本给每次转换准备一个独立 profile：

```
-env:UserInstallation=file://${profileDir}      # profileDir = <scratch>/glibc-profile
```

真机上这条**让 soffice.bin 一声不响地退出 81**（stderr 空、不产文件），桥接照例回退
WASM —— 现象是 `capabilities` 说 `native`、`convert` 返回 `backend: "wasm"`。

同一份 `.odt`，把参数删掉立刻成功。挨个试过去全部 81：

| 写法 | 结果 |
|---|---|
| `-env:UserInstallation=file://<宿主 scratch>/glibc-profile` | 81 |
| 同上，但先把 profile 目录 `rm -rf` 再建 | 81 |
| 同上，指向容器内 `/tmp/loprof` | 81 |
| `--guest-env HOME <已有目录>`（让 LO 去用它） | 81 |
| **不带 profile 参数（HOME=/root 默认）** | **rc=0，2.6 s 出 20 969 字节 PDF** |
| `--guest-env HOME /tmp/<不存在的目录>`（让 LO 自己建） | rc=0 |

规律是「目标 user installation 目录**已经存在**就 81」，让 LO 自己创建才正常 ——
机制没深究（大概率是 proot `--link2symlink` 下 LO 的目录创建/校验走岔了）。最终
选择**不给 profile 参数**：容器默认 profile 连续两次转换都正常，而 Kit 本身有
`acquire()` 串行化转换，共享 profile 是安全的。

## 4. 预置脚本：三处 `soffice` 全部改指真身

`tools/prebuilt/wrappers/kxxy-glibc-provision.sh` 里原来的判定是

```sh
in_guest 'command -v soffice >/dev/null 2>&1'   # 已装？
in_guest 'soffice --version'                     # 装好了？（永远失败）
```

后者在 proot 里恒失败 ⇒ 离线包明明装成功了，却**不写戳**、报预置失败。现在统一走

```sh
LO_BIN=/usr/lib/libreoffice/program/soffice.bin
lo_ok() { in_guest "test -x $LO_BIN && $LO_BIN --version >/dev/null 2>&1" 2>/dev/null; }
```

`tools/lib/seeds.mjs` 里 `soffice` / `libreoffice` 两条命令垫片的 `exe` 也一起改指
`soffice.bin`（垫片是「容器内绝对路径 + proot」渲染出来的，指向 oosplash 就是一条
必然 127 的命令）。

## 5. 顺手两处

- **离线包回收**：五个离线包各自「装成功」时会删掉自己。但**重装扩展会把它们原样
  放回来**，而此时所有目标都已有戳、`offline-all` 一条都不用装 ⇒ 580 MiB 白占设备
  空间。新增 `prune_bundles_if_done()`：五个戳齐全就清掉 `provision/*.tar.gz`
  （`KXXY_PROVISION_KEEP=1` 仍然保留）。
- **`all` 的退出码**：原来只有最后一条（`prov_torch`）的状态会被
  `[ "$?" -eq 0 ] || rc=1` 看到，前面 julia / dotnet 装失败也照样退 0。现在逐条记。
