# Codex 侧栏插件

此插件挂载 DSH `0.2.1-rc.5` 的正式右侧栏，不替换主对话，不解析终端文字。固定原生运行时为官方 Codex `0.167.0`、`aarch64-unknown-linux-musl`。

## 执行引擎与协议

| 引擎 | 模型协议 | 执行方式 |
| --- | --- | --- |
| Codex CLI · 官方账号 | 官方 Responses | Codex 原生线程、工具和审批 |
| Codex CLI · 自定义模型 | Responses | 原生直连指定服务 |
| Codex CLI · 自定义模型 | Chat Completions / Anthropic Messages | 本机 Responses 兼容桥转换协议，工具仍由 Codex 执行 |
| 工作区助手 | 三种协议 | HTTP 模型 + 应用提供的目录、文件和命令工具 |
| 仅聊天 | 三种协议 | 无文件/命令工具，可发送用户明确引用的文本文件 |

**原生 CLI 已包含在当前 app-process 发行构建中。**它使用 Android 应用普通权限，不具有额外的内核级工作区沙箱；工作目录只是任务起始目录，不是原生 CLI 的权限边界。只有经过固定二进制、运行清单、实际应用 UID/SELinux 域及 Shell 检查后才启用原生执行。

原生审批默认保持 `untrusted`。当前会话可通过“访问范围”选择权限：工作区助手支持真正的只读（没有写入/命令工具，执行层也拒绝）；原生只读沙箱尚未通过设备验证，因此明确不可选。完全访问必须经过短期、单次、绑定线程/模型/工作区/连接代次的二次确认，原生映射为 `never`，HTTP 助手免逐项审批但仍保留路径、凭据文件与资源边界。完全访问不成为全局默认、不继承到编辑分支，重连/重启/模型配置或工作区变化后失效，运行中的完全访问任务会被中断。两者都不提权、不关闭 SELinux。原生请求批准具体弹窗由 CLI 决定，不能保证每次写入必弹窗；可靠无工具原生模式尚未验证。

## 配置模型

在侧栏“设置 → 模型服务”中选择引擎、协议、服务地址、认证方式及模型 ID。可获取服务的模型列表，也可直接手填 ID；列表接口不存在不等于推理接口不可用。

- 协议：OpenAI Responses、OpenAI Chat Completions、Anthropic Messages。
- 认证：Bearer、`x-api-key`、`api-key` 或无需密钥。Anthropic 的版本头按该协议设置；不要把认证头重复塞进附加请求头。
- 地址：填写服务给出的 API 基础地址，或完整的 `/responses`、`/chat/completions`、`/messages` 地址。不会猜测并补上 `/v1`，不会失败后静默更换地址或协议。
- 高级配置：受校验的附加请求头/查询参数、显式兼容预设、角色/token 字段、推理选项和输出预算。预设只在用户选择时应用，不按模型名称猜测能力。
- 编辑 API Key 时留空保留原值；无需密钥时可不填。附加头/查询参数值不会返回页面，编辑框留空保留，输入 `{}` 清空。
- `parallelToolCalls` 兼容开关表示是否发送并行控制参数；工作区助手默认发送 `parallel_tool_calls:false`，原生兼容桥按 CLI 请求传递。`store` 开关仅控制是否发送 `store:false`，不会要求上游保存响应。

**高级 HTTP 兼容项主要作用于工作区助手、本机兼容桥和模型检查。**原生 Responses 直连的请求由 Codex 自己构造，不能保证 HTTP 角色、token 字段、预算等覆盖项作用于原生直连；认证、附加头/查询参数和模型支持的推理强度有相应原生接线。

保存不访问模型服务。点击获取列表、检查或发送消息才产生请求。检查会发送少量测试文本，可能计费；工具检查只交换固定测试值，不读取工作区、不执行文件或命令工具。

## 已保存不等于已验证

模型卡片区分配置保存和能力检查：

1. 文本回复：验证实际推理接口。
2. 流式回复：验证 SSE 和完整终态；JSON 兜底不能冒充流式通过。
3. 工具回传：验证一个无副作用测试工具、完整参数、工具结果及后续回复。
4. 原生环境：独立展示 CLI 是否已连接并通过本机运行检查。
5. 原生完整工具链：HTTP 检查不会把这一项标为已验证。

最近检查结果与配置版本绑定；保存修改后失效。测试未保存的草稿不会认证另一份已保存配置。错误保留安全分类、状态码或参数信息，不显示原始上游错误正文和凭据。

## 线程、历史和数据边界

- 模型切换统一从新对话开始，旧历史保留。服务地址、模型 ID、协议、认证类型或影响路由的附加头/查询参数改变，不能继续把旧历史发给新配置。
- 单独更新密钥不改变服务路由；正在进行的请求继续使用已接受的配置快照，下一次空闲发送刷新原生线程凭据。兼容桥保持同一线程的私密回放状态。
- CLI 重连后先恢复线程，再发送新请求；本地有历史不等于新 app-server 已加载线程。超时或断连的已提交任务不会自动重发。
- 自定义助手只回放已完成的历史。旧聊天可通过“启用开发工具”创建助手线程，保留上下文而不执行旧任务。
- 输入框发送成功只清理提交时的草稿与引用，不覆盖等待期间的新输入。
- 文件引用和工作区工具都屏蔽凭据路径，包括 `.env`、`.ssh`、`.npmrc`、`sidebar-models.json` 等；引用限制为工作区内 128 KiB 文本，最多五个。

配置保存在 `KXXY_CODEX_HOME/sidebar-models.json`，线程索引/工作区助手历史在 `sidebar-threads.json`。目录 `0700`、文件 `0600`，原子写入；这是应用私有目录中的**明文凭据**，不是加密保险箱。配置读取支持版本 1/2；新写入版本 2，非法条目保留并逐项提示，不因一条坏配置隐藏全部有效模型。

上游密钥、附加头/查询值、私密推理签名和 provider 回放不进入浏览器快照。原生 Responses 直连需把凭据交给 CLI，因此不能声称外部 CLI 自有存储从不记录配置。其他协议的本机桥只把独立随机本机凭据交给 CLI。

## 本机兼容桥的明确限制

`responses-bridge.mjs` 仅监听 `127.0.0.1` 随机端口，校验 Host、Origin、随机路由与独立令牌；服务地址由服务器绑定，调用者不能指定任意目标 URL。停止/断连会取消上游请求，不自动重试。

- 支持文本消息、函数工具、命名空间工具及明确支持的自由文本工具包装。
- 自由文本工具包装为字符串参数，固定已知 grammar 仅在显式兼容模式下处理；不声称上游仍执行原 grammar 约束。
- 文本真实增量输出；工具必须在完整终态、参数校验通过后才交给 CLI。截断、未完成或错误流不会伪造 completed。
- 不支持的托管搜索、工具搜索、多模态和结构化输出等明确报错，不静默丢弃。桥模型禁用托管搜索/远程 compact，使用固定 CLI 可表达的本地能力设置。
- 服务明确不支持并行控制时，将 CLI 的“允许并行”收窄为单工具并在响应 metadata/header 标注；明确无推理能力的模型可忽略 CLI 的默认 effort，仍有明确告警，不伪造推理。模型声明了推理档位但请求不匹配时继续拒绝，不默选其他档位。
- Anthropic 的 thinking/signature 等私密回放只保存在同一绑定的有界进程内缓存。跨绑定、内容被修改、缓存过期或应用重启后不能伪造签名；需要回放却找不到时要求新建线程。
- 不承诺任何声称“OpenAI-compatible”的服务都支持所有原生 Codex 工具。先做分级检查，再用实际工作区任务验证。

## 侧栏与移动端

采用 A「对话优先」：紧凑顶栏、按真实顺序展示正文/相邻过程组、底部单行 `+ / 访问范围 / 模型 / 独立强度 / 发送或停止`。模型菜单保留搜索、协议分组和管理入口；工作模式在 `+` 菜单中明确选择。过程、长正文、代码、日志和差异分层折叠，手动开合按稳定消息标识保留；完成 Markdown 缓存，流式内容直接来自真实快照，不用定时逐字动画。上翻暂停跟随，显示新内容入口，加载旧历史保持锚点。

长模型名和窄侧栏不应挤掉发送按钮；说明弹层保持可访问的对话框语义，并避开移动插件的通用设置弹窗选择器。输入框自适应高度，移动端 Enter 换行，桌面支持 Enter 发送、Shift+Enter 换行，输入法组合期间不误发。运行/待审批状态跨设置和历史视图可见。

消息下方常驻用户复制/修改、助手复制整轮 Markdown/提出修改/重新回答/详情。修改前确认并新建分支，原历史和实际文件不回滚；请求幂等账本与新分支接收锁阻止重复执行。HTTP 重新回答复用已完成工具结果，真实关闭所有工具；原生无法保证无工具重答，因此禁用并解释原因。兼容桥分支仅复制同模型服务且被前缀白名单覆盖的私密回放，无法可靠映射时拒绝，不推测签名。

新的受控 HTTP `write_file` 操作会在私有 `codex-change-journal` 保存有界前后证据（默认最多256项/8 MiB），支持预检/确认撤销。后续编辑、链接/文件身份变化、日志损坏或不完整时拒绝覆盖；执行期失败如实报告部分成功。旧历史、命令造成的任意变化与原生修改没有可靠前像，不开放自动撤销。普通文件系统检查与 rename 间仍有外部竞态边界，不宣称内核事务。日志为应用私有明文数据，不返回前像给页面或模型。

文件候选搜索、完整 IDE 文件树和云端任务不在本轮范围内。

## 装配与验证

`build-runtime.mjs` 自动收集插件，`stampCodexPlugin()` 生成资产指纹。新增协议模块纳入构建、runtime 和 Android 安装完整性校验。仅更改插件时可用 `tools/restamp-codex-plugin.mjs` 增量重封；插件文件、runtime manifest 与 APK metadata 指纹必须一致。

当前 app-process 运行时含固定 `codex` 和 `lib/codex/runtime.json`，不含 bwrap。构建不自动下载 CLI；既有 workspace-sandbox/bwrap 路线是历史实现，不应与当前 app-process 能力混为一谈。

本地回归入口（Node 24）：

```text
node --test tools/test-codex.mjs tools/test-codex-custom.mjs tools/test-codex-provider.mjs tools/test-codex-workspace.mjs tools/test-codex-mode.mjs tools/test-codex-native.mjs tools/test-codex-protocols.mjs tools/test-codex-bridge.mjs tools/test-codex-diagnostics.mjs
```

测试使用本机模拟服务、虚拟凭据和独占临时目录，不使用用户真实账号。FakeTransport、HTTP 桥测试、浏览器夹具、真实 CLI 及 Android 真机是不同验收层，结果分别记录；不得用测试替身通过来证明真机模型往返已经通过。具体本轮结果见 [多协议兼容说明](../../docs/codex-model-compatibility-2026-11-11.md) 及 `AI_HANDOFF.md`。
